### Template Engine (LIVE since sprint-2/07 - the third platform engine, email surface)
Tenant-designed email templates over a block-document model + ONE render pipeline; the outbox is surfaced as an Email log. Plan: `documentation/plans/sprint-2/07-template-engine.md`. **PLATFORM CORE, not an App Store module** (core auth mails render through it; the Workflow engine consumes `render_email`). Research base: `documentation/research/template-engine-builder-landscape.md` (one builder can't serve email+web+badge - separate editors, shared merge-field + brand seams).
- **Block document = the forever-contract** (`types/templates.ts` mirror = `app/template_engine/schemas.py`): `schemaVersion` at root, Section(layout `100|50/50|33/33/33|67/33`)→Column→Block (heading/text/image/button/divider/spacer/socialLinks/brandHeader/brandFooter/customHtml). NEVER store compiled HTML as source - always the JSON tree. Stable section/column/block ids must be UNIQUE within a doc (dnd-kit keeps ONE droppable per id - duplicate `col_1` across sections deadened drop zones; seed generates unique ids + a deep-copy repair pass). Every section/block carries an optional `conditionsJson` (rule-engine visibility, D8).
- **Merge = OWN micro-renderer** (`app/template_engine/merge.py`): `{{ dotted.path }}` substitution ONLY - NEVER Jinja2/eval on tenant content (SSTI→RCE). Values HTML-escaped by default; hrefs + image src scheme-validated (`javascript:`→`#`/dropped). Missing fact = '' in send, loud marker in preview. ONE renderer system-wide - status-engine notification specs render through it too (D10). The vocabulary = a code-side **`TemplateContext` registry** (`contexts.py`, mirrors STATUS_ENTITIES): each context declares fact sources (rule-engine, e.g. `recipient`), merge facts + samples, and **required facts** (save-time 422 - a reset template without `{{resetLink}}` is a broken flow). Modules register contexts + seed platform templates at install.
- **Compiler** (`compiler.py`): block doc → MJML → `mrml` (Rust port, PyPI, NO Node) → Outlook-safe table HTML + derived plain-text sibling. Full pipeline runs **per send at render time** - no compiled-HTML cache (per-recipient conditional pruning + live brand values). `render_email(db, template, tenant_id, facts, rule_objects=)` = the Workflow-engine contract; preview uses the SAME function (`mode="preview"`).
- **Two-tier** (status-engine D7 pattern, `template_repository.py`/`template_service.py`): platform defaults carry `tenant_id NULL` (partial unique index per tier - BL-065 lesson); a tenant's first edit FORKS a tenant copy resolved ahead of the platform row (frontend `router.replace` follows the new id); "Reset to default" drops the fork. The **platform tenant maps to scope `None`** and edits the NULL-tier rows IN PLACE (operator maintains the defaults). System templates: key/context/delete locked.
- **System mails ride the engine (D7)**: `seed_platform_templates` (insert-if-missing - operator edits survive reseed) ports every transactional mail to a platform-tier block template; `email_service` renders engine-first with a legacy-Jinja fallback (a broken template must NEVER block auth mail), and the outbox `template_key` now carries the ENGINE key (`auth.password_reset`, …). Closes BL-038/BL-066 - branded reset/invite mail.
- **Rich text = WYSIWYG toolbar, never typed tags** (`components/platform/email-editor/rich-text-field.tsx`): execCommand → exactly the nh3-kept tag set (b/i/u/a/ul/ol) + merge chips. Typing raw `<i>` into a contentEditable serialized to escaped `&lt;i&gt;` - the toolbar inserts real elements. Text blocks edit in the panel; the canvas renders their HTML read-only (client-sanitized via `lib/sanitize-html.ts` - render-time net atop the nh3 save gate). Headings stay inline plain-text. **contentEditable rule (learned here, twice):** never pair it with `dangerouslySetInnerHTML`/React-managed children - a parent rerender re-applies the stale value and WIPES typing before blur commits (the "text resets / nothing saves" bug); the sync effect must be the single writer.
- **Email log = outbox surfacing (D14)**: `/emails` Resource list with **N-way segments** (shell gained `ResourceListConfig.segments` → renders as SearchSelect, not a toggle row - a status set would stretch the toolbar; binary Active|Trashed stays the segmented control) + read-only detail (NO Edit toggle; Body tab = **sandboxed iframe**). Retry (FAILED|CANCELLED→PENDING, attempts PRESERVED - history honest) + Cancel (atomic `UPDATE … WHERE status=PENDING` → 409 on dispatcher-claim race; cancelled rows retryable). Tenant-scoped - own mail only. Dispatcher retention prune now covers FAILED/CANCELLED by created_at. New core perms `templates.read/manage` + `emails.read/manage`.
- **`tenant_branding` grew socials + footer (D4)**: `socials_json`/`footer_json` (whitelisted keys, 422 on unknown); BrandHeader/BrandFooter/SocialLinks blocks resolve them at RENDER time (live-follow a rebrand). Branding settings UI gained a "Social & email footer" card. **Dev gotcha**: the brand-header logo URL uses `public_base_url` (localhost in dev) - external mail clients (Gmail proxy) can't fetch it, so the logo shows broken in real delivery; works in prod / via a tunnel.
- **Dirty-guard = AlertDialog, not `window.confirm`** (shell-wide, `resource-form.tsx`): the unsaved-changes guard is now `guard(proceed)` - runs immediately when clean, else defers the action behind a styled Discard-changes dialog (Cancel + RecordNav route through it). Every ResourceForm gained it.
- **Tests**: `tests/test_template_engine.py` (40 cases - merge security, compiler goldens, pruning, validate_doc 422 matrix, two-tier, system guards, engine-rendered system mails, notification template path, email-log retry/cancel/retention); E2E `e2e/templates.spec.ts` (3 journeys + report `documentation/plans/sprint-2/07-template-engine-test-report.md`). dnd-kit drag-drop is asserted in Vitest - the retired E2E runner's mouse-event `dragTo` doesn't drive dnd-kit's pointer sensors.
