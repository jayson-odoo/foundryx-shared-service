# Multi-tenancy, auth, RBAC, impersonation, auth hardening

> Moved verbatim from `CLAUDE.md` on 2026-09-05 (slim-index restructure). The rules here still bind; `PRINCIPLES.md` governs on conflict. Update THIS file when the engine changes.

### Multi-tenancy (SaaS - LIVE since sprint-1/07)
Foundryx EMS is a **multi-tenant SaaS**: many tenants on one deployment, one shared DB. The real tenancy model shipped in `documentation/plans/sprint-1/07-tenant-core.md`:
- **`tenant_id` on every tenant-scoped table** (core `public` tables and module tables alike). **Every repository query is tenant-scoped** - the tenant comes from the authenticated context (JWT claim), never from client input.
- **Tenant resolution = subdomain slug** (`acme.foundryxems.com`; dev `acme.localhost:3001` - browsers resolve `*.localhost`). Frontend `lib/tenant.ts deriveTenantSlug(host)` → NextAuth `authorize()` sends `tenantSlug` in the login POST; backend `AuthService.resolve_tenant` maps slug→tenant. Missing slug / bare host = `default`. Slugs: lowercase kebab 3-63, **immutable after creation**, reserved list mirrored frontend (`lib/tenant.ts`) + backend (`models/tenant.py RESERVED_TENANT_SLUGS`).
- **Tenant lifecycle** rides the core **`statuses` foundation** (`app/models/status.py` - `entity_type/key/category/label/color`, plan 07 §3): **code branches ONLY on the fixed `category`** (`ACTIVE/SUSPENDED/ARCHIVED`); label/color are display, editable later (BL-037; full engine BL-027). `Tenant.signin_allowed` is the single chokepoint - checked at login AND per-request in `_resolve_user` (suspend kills live sessions on their next request; archived = hidden in the console's Archived view, data intact; hard purge = BL-035).
- **Platform tenant** (`is_platform=true`, slug `platform`, seeded) hosts the operator team. `require_platform_permission(key)` = `require_permission(key)` AND `user.tenant.is_platform` (double lock). Platform permission keys live in `app/permissions/platform_permissions.csv` (module `platform`) and are **hidden from tenant callers** in `GET /permissions`; tenant Admin grant = core keys + INSTALLED-module keys (`seed.tenant_admin_grant(db, tenant_id)` - install-aware since plan 08). `User.tenant` + `Tenant.status` are `lazy="joined"` - the lifecycle/platform checks cost no extra query.
- **Provisioning** (`TenantService.provision`, POST `/platform/tenants`): tenant + seeded system roles (`seed_tenant_roles`) + first admin user (operator-set temp password - invite email BL-033) in ONE transaction. Self-signup (BL-032) must reuse this service.
- **Platform Console** = `/platform/tenants` (Resource shell clone; Active|Archived status views; suspend/reactivate/archive actions; "Open tenant" opens `<slug>.<domain>` via `lib/tenant.ts tenantUrl`). Menu section gated by `MenuItem.platformOnly` + `session.user.isPlatformTenant` + `can('tenants.read')`. Operator cross-tenant impersonation = BL-047.
- **Association `tenant_id` is derived, not defaulted** (BL-015 fix): `user_roles.tenant_id`/`role_permissions.tenant_id` resolve from the OWNING ROLE at insert (`models/permission.py tenant_id_from_role`) - never reintroduce a static default.
- **Isolation strategy is shared-DB + `tenant_id` row scoping** (not schema-per-tenant). Orthogonal to module schema-isolation: module schemas isolate *features*, `tenant_id` isolates *tenants' rows* within those tables. One deployment = one code version for ALL tenants - chargeable upgrades are **version-gated features** (`tenant_modules.installed_version`, plan 08), never per-tenant code.

### Auth flow (deliberately diverges from sorento_crm)
FastAPI owns auth end-to-end - it validates credentials and issues the JWT. NextAuth is only a session carrier: `CredentialsProvider.authorize()` (`app/api/auth/[...nextauth]/auth-options.ts`) POSTs to FastAPI `POST /auth/login`, stores the returned `access_token` in the NextAuth session, and `lib/api-client.ts` attaches it as `Authorization: Bearer <jwt>`. sorento_crm instead has NextAuth+Prisma own auth - foundryx does NOT. **Prisma is fully stripped** from the frontend; ignore Prisma references in the upstream Metronic README.

Login contract: `POST /auth/login {email,password,tenantSlug?}` → `{access_token, token_type, user:{id,tenantId,isPlatformTenant,email,name,avatar,roles:[{id,name}],permissions:[string],status}}`. Users are **multi-role** (M2M `user_roles`); the JWT carries `tenant_id` + `roles[]` claims (NOT permissions - see RBAC below); `get_current_user` resolves the user tenant-scoped via `UserRepository` and re-checks the tenant lifecycle per request. Unknown slug = uniform 401; suspended/archived tenant = 403 "This tenant is suspended." (`roleId`→`roles[]` sprint-1/02; `permissions[]` sprint-1/03; `tenantSlug`+`isPlatformTenant` sprint-1/07.) **Deploy note:** sessions issued before a new session field existed need one re-login (`permissions[]`, `isPlatformTenant`).

**Auth is platform core, NOT an App Store module** - it's the foundation every module plugs into (`Depends(get_current_user)`, core `public.users`). Don't package it as a module; modules depend on it.

### RBAC & permissions (sprint-1/03 - the gating contract every feature uses)
Every feature is **RBAC-controlled**. A permission is a flat key `"<resource>.<action>"` (e.g.
`users.create`, `orders.approve` - custom actions are first-class). Plan: `documentation/plans/sprint-1/03-roles-permissions.md`.
- **Catalog** is a global `permissions` table (no tenant scope) **synced from per-module CSV**:
  `<module>/backend/permissions/permissions.csv` (columns `resource,resource_label,action,action_label,description`).
  Core's CSV lives at `service_backend/app/permissions/permissions.csv`; `PermissionService.sync_permissions(module, rows)` upserts + deletes-by-module (App-Store install/update/uninstall), run for core at bootstrap/seed (core = "module zero"). **Add a permission = add a CSV row** (not code).
- **Grants** = `role_permissions` M2M (tenant-scoped via the role). **Implied-read:** any granted non-read action forces `<resource>.read`, normalized server-side in `RoleService` (blanket, incl. custom actions).
- **Enforcement (backend = the real boundary):** `require_permission("key")` dependency (`app/dependencies.py`) - per-request DB resolution via `effective_permission_keys(user)` (union over roles, read fresh - RBAC edits apply immediately; NOT from the JWT). **No superuser bypass** - but note since sprint-1/08 the tenant Admin grant is core + **installed-module** keys (`tenant_admin_grant(db, tenant_id)`; AppStoreService grants/revokes on install/uninstall), and platform keys additionally need platform-tenant membership (`require_platform_permission`). `GET /permissions` + `RoleService._grantable` hide/drop uninstalled modules' keys for tenant callers. Gate every protected endpoint; auth/`/auth/me`/health/`/me/preferences` stay perm-free.
- **Frontend gating (UX only):** `useCan()` (`hooks/use-can.ts`) reads `session.user.permissions`; `<RequirePermission permission>` wraps pages → friendly `NoPermission` page (never a raw 403); Resource shell honors `ResourceAction.permission` / `ResourceListConfig.createPermission` / `ResourceFormConfig.editPermission`.
- **Roles** carry `description` + `is_system` (seeded roles are system = delete-blocked, but name/desc/perms editable; toggle in Settings). Roles list/form clone the Resource shell; `GET /roles` is paginated, **`GET /roles/options`** is the lightweight (id,name) picker for the user form (authenticated-only). Endpoints: `/roles` CRUD + `/at` + `/export` + `/{id}/users` (assigned/assign/remove) + `/{id}/assignable`; `/permissions` (catalog).
- **Filter translator is entity-agnostic** (`services/filter_translator.py`): `translate_filter(group, columns, special?)` - each service passes its own whitelisted column map (+ optional resolver for M2M fields like users' `role`). Never hardcode one table.

### Impersonation (sprint-1/03 - test access as another user)
An authorized user (`users.impersonate`) browses with a target's **effective permissions**. `impersonation_sessions` table; the effective user is signaled per-request via the **`X-Impersonate-User-Id`** header (`lib/api-client.ts` attaches it from `lib/impersonation-store.ts`), honored by `get_current_user` **only** while an active session row matches (admin,target) AND the real user holds `users.impersonate`. **Security invariant: effective user = target (perms/view); actor = real admin (`get_actor_user_id`)** - writes are never attributed to the target. `get_real_user` (ignores the header) gates the `/impersonation/{start,stop,current}` endpoints so a session can't end its own. Rules: not self, target active + not an impersonator, **impersonator must hold ⊇ the target's permissions** (no escalation), same tenant. Collapsible amber banner in `app/(protected)/layout.tsx`; `useCan` reflects the target while active.

**Login = the reference implementation of the full DX + layering** (`app/(auth)/signin`, `components/auth/`, `hooks/use-signin`, `services/auth-service`; backend `api/v1/auth.py` → `services/auth_service.py` → `repositories/user_repository.py`). Current security posture: uniform `401 "Invalid email or password."` (no user enumeration), dummy-bcrypt on the not-found path (timing parity), server-side password policy, bcrypt 72-byte truncation in `security.py` (do NOT remove - bcrypt raises on >72 bytes). Remaining gaps tracked in `documentation/backlogs/backlog.md` (infra-vs-auth error messages BL-005, real captcha BL-041, per-tenant security policy BL-039).

### Auth hardening (LIVE since sprint-1/10 - forgot-password, rememberMe, throttle)
Plan: `documentation/plans/sprint-1/10-auth-hardening.md`.
- **Forgot-password** = `POST /auth/forgot-password {email,tenantSlug?}` - public, **always 200** with the uniform message (dummy token-gen on the miss path; outbox behavior must never leak existence). Issues a single-use token (invalidating the user's prior outstanding tokens), TTL `reset_token_ttl_minutes` (60m; invites `invite_token_ttl_minutes` 7d); email links → **`/change-password?token=`** (invites too). Redeem = existing `POST /auth/set-password` (single-use + expiry + full policy). Pages: `/reset-password` (request) + `/change-password` (redeem) on the login reference DX (`use-forgot-password`/`use-change-password` → `password-service` trio).
- **Password policy single source per layer:** backend `app/schemas/password.py validate_password_strength` (upper/lower/digit/special, 8-72) applied to `SetPasswordRequest`, `SignupRequest`, **`TenantProvisionRequest.adminPassword`**; frontend mirror = `app/(auth)/forms/password-schema.ts getPasswordSchema()` (tenant provision schema reuses it). Add a password-accepting schema → attach BOTH.
- **rememberMe (D4):** `LoginRequest.rememberMe` → JWT exp `remember_me_expire_minutes` (30d) vs `access_token_expire_minutes` (24h). NextAuth `maxAge` = 30d but the **backend JWT exp is the boundary** - `api-client` calls `signOut({callbackUrl:'/signin'})` on any **401-with-token** (backend 401 ⇔ token invalid/expired; permission problems are 403s - keep it that way).
- **Throttle (D5/D6):** `auth_throttle` table + `app/services/throttle.py` (`ThrottleStore` protocol; `DbThrottleStore` Postgres impl; Redis adapter = BL-040). Email scope: 5 fails/15m → 15m TEMP lock (success resets; never permanent - victim-DoS). IP scope: 20 fails/15m (login fails, every forgot-password request, failed set-password redeems). Checks run **before bcrypt**; over-limit = `429` + `Retry-After` (frontend `lib/throttle-message.ts` renders "~N minutes"; signin shows the backend detail - authorize() can't see headers). `trust_proxy_headers` (default false) gates X-Forwarded-For. Stale rows pruned by the dispatcher housekeeping pass. **E2E caveat:** locally EVERYTHING shares IP `127.0.0.1` - suite runs pump the shared bucket and 429 later manual testing/parallel specs; `DELETE FROM auth_throttle` when login flows 429 unexpectedly (local `.env` carries `THROTTLE_IP_MAX_FAILS=200` to soften this; one-command suite wiring = BL-061). The email-scope lock (5/account) is kept tight on purpose - that one you *want* to feel locally.
- **Signup parked (D3):** kill-switch `signup_enabled` (backend 404) + `NEXT_PUBLIC_SIGNUP_ENABLED` (`lib/auth-flags.ts` - signin link hidden, `/signup` + `/verify-email` render not-found). reCAPTCHA stub deleted (was never verified server-side); real captcha = BL-041, self-signup = BL-032.
