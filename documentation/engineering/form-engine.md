### Form Engine (LIVE since sprint-3/01 - the 5th core engine; slice 1 MERGED)
Drag-drop form builder + runtime renderer + server validator - Typeform/Tally-class, plan `documentation/plans/sprint-3/01-form-engine.md`. **PLATFORM CORE, not a module** (`app/form_engine/`, core `public` tables, core permissions CSV) - consumed by future registration/submission/review clusters; composes the rule + status + workflow engines. Built in **2 slices** + a builder-enhancements pass, all **MERGED to main** (`baffcaf`): 01 = builder + publish + internal fill + submissions + scoped statuses; 02 = public anonymous surface + `form.submitted` trigger + file/signature uploads; enhancements = aggregates, Table block, integer/decimals, formula builder, drag, file-view, record-nav.
- **Engine = dumb capture; binding = workflow (D2).** The engine knows nothing about users/participants/events - one generic `form_submissions` store (`answers_json`, pinned `version_id`, `status_id`, nullable `user_id`, optional inbound polymorphic `subject_type`/`subject_id`). Everything that *reacts* to a submission (create participant, send confirmation) is a workflow on the `form.submitted` trigger (slice 2). Zero built-in bindings.
- **Doc = forever-contract block tree** (`types/forms.ts` mirror = `app/form_engine/schemas.py`, parity-pinned by `tests/test_form_parity.py`): `{schemaVersion, pages[]}` → Section (titled, optional 2-col, `conditionsJson`) → Field (stable `key` = answer key, relabel never breaks refs; `conditionsJson`). Full D7 taxonomy v1 (text family, number, choice ×5, date/datetime, file, **signature** canvas→PNG, rating, **address** composite, **repeater** rows, **computed**, display). `payment` deferred BL-086 (no provider → would violate foolproof-UI). Choice options `{kind:'static'}`-only v1, shaped for `{kind:'entity'}` (BL-087).
- **Computed = arithmetic-only OWN parser** (`computed.py` + `lib/computed-expr.ts` mirror): `+ − × ÷`, parens, sibling refs - NEVER eval/Jinja (anti-SSTI house line). Live client recompute + authoritative server recompute (client value ignored on submit).
- **Versioning = workflow pattern (D9).** Mutable `draft_definition_json`; **Publish** runs `validate_form_doc` (422 `{problems}`: dup/missing keys, empty page, computed forward/non-numeric ref, condition forward-ref, repeater dup sub-keys, bad pattern) → snapshots `form_versions` + sets `current_version_id`. Fill serves ONLY the published version; **preview renders the draft**. **Submissions pin `version_id`** - re-render faithfully forever (a reviewer sees the form as it was even after the draft is renamed/republished). Version history = own paginated endpoint.
- **Submit pipeline = the boundary (D14, `validation.py` + `lib/form-validate.ts` mirror)**: server re-derives the VISIBLE set via rule-engine `evaluate` (fail-closed) → **hidden field answers silently DROPPED** (never stored, never 422) → required-if-visible → per-type constraints + choice-membership against the version's options + computed recompute + repeater row min/max + address sub-key whitelist → 422 `{fieldErrors}` per-field map (inline highlight + jump-to-page). Condition facts = `answers.<fieldKey>`, **earlier fields only** (document order bans cycles + forward refs).
- **Submission lifecycle = the STATUS ENGINE via a new SCOPED-MACHINE extension (D4 - generalizes beyond forms).** `statuses.scope_id` (nullable, indexed; migration `3e4f5a6b7c8d`) - for entities registered `scoped` (first adopter `form_submission`, `scope_attr='form_id'`), each owning record carries its OWN graph: **materialized at scope creation** (`app/status_engine/scoped.py` - seed Draft `is_initial`+`is_active`, Submitted `is_active=false`, one edge), tenant-owned from birth (NO two-tier fork). `transition`/`available_transitions`/`fireable_edge_ids` scope-guard (a submission can never move onto another form's graph - same guard class as polymorphic target_id). **Flag semantics for scoped (D4): `is_active` = "respondent may still edit answers"** (Draft yes, Submitted no), so the executor's hide-inactive-targets rule applies ONLY to unscoped entities. (Canvas-badge gotcha: the StatusNode renders `!is_active` as **"Inactive"** - the generic word reads as "disabled" and confuses users on a form's Flow tab where it means "locked for edits"; relabel to "Locked"/"Editable" for scoped graphs = BL-091 candidate.) Scoped entities are HIDDEN from the global Statuses list (graph lives on the owner's Flow tab; the graph endpoint requires `scopeId`). Submit fires the seeded Draft→Submitted edge through the one executor; the full pre-existing status-engine suite stays green (tenant lifecycle untouched - the load-bearing requirement).
- **Window + caps on the form row (D10)**: `opens_at`/`closes_at` (closed→409), `max_submissions` (count-guarded), `submission_limit_per_user` (greyed out for public/anonymous forms - unenforceable). Access `internal`|`public` v1, `portal` reserved.
- **Public anonymous surface (slice 2, D11/D12).** Pre-auth `GET/POST /public/forms/{tenant_slug}/{form_slug}` (`forms.public_router`, `app/api/v1/forms.py`). **Tenant slug rides in the PATH, not the subdomain** - the browser hits the API origin directly so the subdomain can't survive on the Host header; the frontend derives it (`deriveTenantSlug`) and the `/public/branding` precedent is reused. **Frontend public route MUST live under a literal `public/` segment** (`app/(public)/public/forms/[slug]/`): a route group `(public)` is invisible in the URL, so `(public)/forms/[slug]` collides with `(protected)/forms/[id]` ("different slug names for the same dynamic path" - a BUILD error). Unknown tenant / suspended tenant / non-public / unpublished form = a **uniform 404** (no enumeration); a published-but-closed/full form returns a 200 `state` (`open`|`closed`|`full`) so the page shows a friendly message. **Security (D12):** own per-IP throttle bucket (`THROTTLE_SCOPE_FORM_PUBLIC` - never shares the login bucket); a render-time **honeypot** field (`FORM_HONEYPOT_FIELD`, off-screen) → a non-empty value returns 204 but stores NOTHING (never tip off the bot); submit is anonymous (`user=None`), per-user cap unenforced. The public fill page reuses the ONE `FormRenderer`; `publicFormService` (no-auth `publicFetch`) + `usePublicFormFill`.
- **`submit()` is the shared boundary for internal + public + anonymous** (`FormService.submit(tenant_id, form_id, user|None, answers, uploads?)`). It emits a **`form.submitted` workflow event** (slice 2) on the SAME commit's after-commit drain when the row actually reaches Submitted - failure-isolated, so a broken/slow workflow can NEVER 500 a (public) submit.
- **File / signature uploads = sniff-gated quarantine (slice 2, D12).** Submit accepts EITHER JSON or multipart (`file:<fieldKey>` parts + a `payload` JSON part; files read with a CAPPED read so an oversize body is never buffered). `app/uploads.py detect_upload_mime` sniffs by magic bytes - **images + PDF only** v1 (SVG excluded; declared content-type ignored). Bytes are stored ONLY after the row exists (the quarantine key `forms/{form_id}/{submission_id}/{field_key}/{n}` needs the submission id), so a validation failure leaves no orphan blobs; the provisional file/signature answer is sniff-validated BEFORE `validate_submission` and the placeholder is swapped for the real `storage_for_tenant` key after store. **Gotcha: a plain JSON column won't track in-place mutation of the SAME dict object** - `_store_uploads` mutates `clean` then the row must be reassigned a NEW dict (`json.loads(json.dumps(clean))`) or SQLAlchemy misses the swap (the placeholder persists). Served back ONLY through the authed CSP-sandboxed route `GET /submissions/{id}/files/{fieldKey}/{n}` (`sandbox` + nosniff + private-cache; presigned URLs never immutable-cached). Frontend builds multipart via `lib/form-submit-body.ts` (signatures stay inline data-URLs in JSON - the backend decodes them). Authed in-UI download (`<img>`/link can't carry the Bearer) = BL-092.
- **Permissions (D19)**: `forms.read/manage`, `submissions.read/manage` (core CSV, seeded to tenant Admin). **`GET /{id}/fill` + `POST /{id}/submissions` are gated `get_current_user` ONLY** - any authenticated tenant user fills/submits (filling ≠ administering). Public endpoints (slice 2) are perm-free.
- **Frontend**: sidebar **"Forms"** (all 3 menu arrays, `forms.read`). `/forms` Resource list + tabbed ResourceForm detail: **Builder** (EmailEditor-skeleton `components/platform/form-builder/` palette·canvas·settings, dnd-kit + click-to-add, RuleBuilder conditions, `useHistory` undo/redo) · **Submissions** (embedded scoped Resource list, status segments, author-pinned answer columns, CSV export, graph-driven row transitions) · **Flow** (the form's scoped status canvas - reuses `EntityFlow` with `scopeId`) · **Settings** · **Versions**. ONE runtime renderer `components/platform/form-renderer/` serves internal fill / author Preview / read-only submission view (slice-2 public fill too). Service trio (`form-service.{ts,mock,real}`), `ApiError.detail` now carries the structured 422 bodies.
- **`form.submitted` workflow trigger (slice 2, D13).** A new core `TriggerDef` (`registry.py`) with a searchable `form` config field (NodeField type `form`); `trigger.answers.<key>` outputs are **dynamic per selected form** - `GET /workflows/metadata` now returns `forms[]` (published forms + their answer-field keys) and the editor's `{ }` picker lists them. NO new triggerable entity: the event uses `entity_type="form_submission"` + `action="submitted"` + `extra={formId, submissionId, answers}`; `_trigger_types_for("submitted")→["form.submitted"]`, publish denormalizes `trigger_entity_type="form_submission"` (the indexed match) and `_passes_refine` narrows by `config.formId` (per-form selectivity). The executor flattens the payload → `trigger.formId`/`trigger.submissionId`/`trigger.answers.<key>` (substitution-only, anti-SSTI). **Boundary vs status-notification (slice-2 rule):** an atomic transition-local confirmation = a status-engine notification; a multi-step/conditional/cross-entity reaction = a `form.submitted` workflow.

- **Builder enhancements (slice-2 branch, user-iterated, all on `sprint-3/02`).** Layered on top of slice-2 core:
  - **Computed aggregate functions** - the `computed.py` / `lib/computed-expr.ts` parser gained `sum/avg/min/max(repeaterKey.subKey)` + `count(repeaterKey)` (dotted IDENT in the tokeniser; `AggregateRef`s collected separately from scalar `field_refs`; eval reads the row-array from the values dict). Publish gate validates the aggregate's repeater/table is an EARLIER row-container + the column numeric. `field_refs`/`aggregate_refs` split.
  - **`table` field type (PO/SO/invoice line items)** - a SECOND composite alongside `repeater` (repeater = stacked "repeating forms"; table = tabular line items). `FormTableConfig {columns, showRowNumbers, min/maxRows}`; column types `text|number|integer|select|date|computed|fixed`. **Per-row `computed` column** evaluated over that row's earlier cells (reuses the computed parser); **`fixed`** column = server-stamped constant (client value ignored), referenceable in computed; **column total `<tfoot>`** (sum/avg/…). Renderer `table-field.tsx` (real `<table>`, `overflow-x-auto` mobile scroll). Server `_validate_table` + `_clean_value` recompute computed/stamp fixed PER ROW (anti-tamper). `validate_form_doc` table gate mirrors the computed-column earlier-numeric rule.
  - **`integer` field type + decimal places** - palette **Number** category lists *Number (decimal)* + *Integer* (the old "Kind" dropdown is gone; legacy `number.integer` flag still honored). `FormNumberValidation.decimals`/`.integer` (+ column-level). Integer inputs block `.`/`,`/`e` keys (`step=1`); decimal inputs pad to N places on blur (1→1.0000) and **error on >N places**. Enforced client AND server (`_number_kind_error`); FE shows the error **live on type** (renderer `setAnswer` runs per-field `validateField`, surfacing format errors but leaving `required` for submit).
  - **Reusable formula-builder popup** (`components/platform/form-builder/formula-builder.tsx`) - a SHELL: init with `{variables:{label,token}[], operators?, validate?}`; operator buttons + searchable variable list (insert at caret) + live parse/ref validation. Opened via a **Build** button on the computed FIELD and the table computed COLUMN (replaced the inline insert-dropdowns).
  - **Drag-to-reorder** (dnd-kit) for table columns AND repeater sub-fields (grip handles, ↑↓ removed). **Click-away deselect** on the builder canvas (selectable cards `stopPropagation`; empty-bg click → `onSelect(null)`).
  - **View uploaded files (closes BL-092)** - submission-detail file/signature chips fetch the authed CSP-sandboxed serve route as a **blob** (`apiFetchBlob` + a `SubmissionContext` carrying the submission id; an `<a href>` can't carry the Bearer) → object-URL opens it. **Submission record-nav** - the detail header has `‹ N / M ›` prev/next (fetches the ordered id list; cap the page size at the endpoint's 200, not 500 → else 422). **Submission list pinned answer columns** head with the field **label**, not the raw key.
  - **Branding asset route 404 (not 500) on a missing local blob** - a DB branding row can outlive its gitignored file; `FileResponse` on a missing path raised → 500. The public form shell falls back to the tenant NAME on logo-load failure (white-label).
- **Adding a form field type is a CHECKLIST (learned via the `integer`/`table` adds + review).** Touch EVERY layer or it half-works: (1) FE `FormInputFieldType` + backend `INPUT_FIELD_TYPES` (parity-pinned - both or `test_form_parity` fails); (2) `NUMERIC_FIELD_TYPES`/`CONDITIONABLE_TYPES` both sides if applicable; (3) palette catalog + icon; (4) `createField` defaults; (5) **`doc-ops.changeFieldType` seed** - the type-SWITCH path is separate from the palette path; forgetting it = the new type's config bag is undefined → unpublishable (the Table bug); (6) renderer `field-input` + `field-read`; (7) validation client (`form-validate`) AND server (`validation.py`) - KEEP THEM IN PARITY (the review caught `validateTable` skipping only `computed` not `fixed`, and a missing `date` cell check); (8) `_clean_value`/clean. A composite (table/repeater) also needs the publish gate + aggregate-container registration.
- **More review-hardened rules (this engine):** decimal-place counts use **Decimal exponent / `toFixed` round-trip, NEVER a `.split('.')` digit count** (sci-notation `1e-7` slips a string count past the max-DP gate, both layers); upload/file errors must be **filtered to the VISIBLE set before merging** into the submit error map (a condition-hidden file field must never 422 - the hidden-fields-never-error contract); a submit endpoint that became multipart-aware (`await request.form()`) must **try/except `request.json()`** on the JSON branch or a malformed body 500s instead of 422; generated keys (`col_N`, `option_N`) must be **unique vs the existing set**, not `length+1` (collides after a middle delete → dup-key publish reject); the submissions list endpoint **caps `page_size` at 200** - any all-rows fetch (record-nav) must respect it or 422.
