### EMS module (LIVE since sprint-3/11, F4 - the first vertical, `app_ems` schema)
The EMS domain spine as the first big **module** (not core, so the platform stays a horizontal base). Plan `11-ems-domain-spine.md`. `modules/ems/` (manifest, db.py `EmsBase`/`app_ems`, per-module Alembic baseline, bootstrap, models, services, routers, importers).
- **Entities**: `profiles` (participant identity, NOT staff `users`; `UNIQUE(tenant_id, lower(email))` dedup, auth columns reserved-not-used - portal = Cluster D); Type→Template→Project hierarchy (`project_types` category, `project_templates` preset owning the eligibility flow + roles/segments, `projects` instances created from a template); `project_participants` registration join (one per profile+project). **Cross-schema FKs to core (`tenants`/`statuses`) = plain indexed columns, NOT DB FKs (BL-030)**; intra-`app_ems` FKs kept.
- **Two-tier status, all on the status engine, zero new engine code**: tier-1 `Profile.status_id` (unscoped, tenant-level Active/Suspended/Blacklisted) + project lifecycle `Project.status_id` (unscoped) + tier-2 participant eligibility (SCOPED, scope=project_id). **`copy_scope(db, entity_type, tenant, from=template_id, to=project_id)`** (new helper in `status_engine/scoped.py`) materializes a Project's own editable eligibility graph by COPYING the template's at create (Option A - per-project copy, not live-inherit).
- **Pure registration into all engines (D9)** via boot `register_engine_entities`: status entities (profile/project unscoped, participant scoped) + terminology labels (project→"Event"…) + importer configs (profile + project-scoped participant find-or-create) + capabilities. UI "Event" via Terminology; canonical name stays `project`.
- **`ems` module wired into conftest** (schema_translate `{EMS_SCHEMA: "omni"}` onto the attached db + `EmsBase.metadata.create_all` + import models before create_all + `AppStoreService.install(default, "ems")`).
- Frontend: Profiles + Events on the **Resource shell** (search/sort/column-prefs/select/export; Profiles importable, id-first export). Tests: `tests/test_ems_spine.py` (8). Report `11-ems-domain-spine-test-report.md`.
- **Management UI shipped (`sprint-3/ems-management-ui`, MERGED 2026-06-18) - first iteration of the spine UI complete.** Closes the deferred detail surfaces (AC-11-01/12/13):
  - **Event Types + Event Templates** = Resource lists (create/edit/delete; backend gained PATCH/DELETE + delete guards - a type still owning templates / a template already used by events can't be deleted, 409).
  - **Template detail** = Details · **Roles** · **Segments** · **Eligibility-flow editor** (`EntityFlow`, scope=template_id). The participant `scope_exists` guard now accepts a template OR project scope owner (`_participant_scope_exists`) - the template's materialized graph 404'd otherwise.
  - **Event detail** = **Participants** (role/segment assign + graph-driven status moves listed as the available next states straight off the scoped graph; bulk import) · **Eligibility-flow editor** (scope=project_id). Roles/segments are **template-owned, shared not copied**, validated cross-template (422 on a foreign id).
  - **Profiles** = detail/form view + tier-1 status change in the list row, the form "…", and **bulk** (target picked, only profiles whose current status allows the move are changed, rest skipped).
  - **Status engine gates participation (deepens AC-11-07):** a `blocks_access` tier-1 status (Suspended/Blacklisted) refuses the profile as a participant - `ParticipantService.add` AND the bulk importer (422) - and the Add picker withholds blocked profiles (foolproof-UI; backend is the real boundary). Tests +6 (14 ems green; status-engine suite stays green).
  - **Pattern for any per-row state move (reused by profiles + participants):** read the entity's status graph, render each outgoing edge from the row's current status as its own "…" item that fires the transition directly (no intermediate dialog), failures toasted. Button label = the **bare target status name** (user mandate - no "Move to" prefix).
