# AutoCount write-back (engineering note)

Contracts of record: `documentation/plans/sprint-5/55-autocount-write-link-contract.md` and `57-autocount-write-qtso-contract.md`. Plan 63: `sprint-5/63-autocount-db1-ready.md`.

- **Optional AutoCount API key.** The autocount connection (auth = none) may carry `apiKey` (secret, encrypted at rest), `apiKeyHeader` (default `X-API-Key`), `apiKeyFormat` (default `{key}`; `Bearer {key}` allowed) and `apiKeyOnReads` (No/Yes, default No: reads carry the header only when Yes). Code: `modules/autocount/write_back/auth.py`. The connection is resolved per action with no cache, so a rotated key applies from the next action. The key is never logged or echoed; an invalid configuration is refused before sending (`AUTH_CONFIG_INVALID`, no value in the text). The CRM never sends or sees it.
- **Write books.** Writes outside the test book are accepted only from the production deploy, with the books listed in `AUTOCOUNT_WRITE_ALLOWED_BOOKS`; `write-capabilities` (57 section 7) reports the effective `book`.
- **Acting user.** Optional `X-Acting-User-Id` and `X-Acting-User-Name` (57 section 2a.1) are stored with `X-Request-ID` on the write action rows and the call log (`write_back/call_log.py`, `person_of`). Invalid or absent = stored empty, never a refusal.
- **AutoCount > Calls.** Read-only view of the per-call log (server-side sort and filter, request and response detail), behind the JWT prefix.
- **Write locks (`write_back/link_lock.py`, lane AUTOCOUNT-SS-POLOCK).** Every row operation that writes a PO (`link_row`, `split_link`, `link_batch`, `relink_row`, `unlink_row`, `resume`, plan 55 link / unlink / relocate) holds a Postgres session advisory lock per PO document, taken BEFORE the per-SO-row locks, on one connection from a small dedicated lock engine (never the app pool). Nested takes in the same call chain (an operation running the plan 55 split link) reuse the held connection through a ContextVar and release only what they took. A lock not won in 30 s, a lock pool that is exhausted, or a lock connection that breaks before the body is `DOC_BUSY` (nothing sent, never stored under the key). SQLite takes no lock. The plan 55 path also counts an `in_progress` operation on the document as busy. In `link_batch`, unresolved link operations on the same PO row (`pending_verification` / `needs_attention`) whose rows the fresh read does not show count against the row's free qty (`QTY_ABOVE_FREE`); a whole-row link reserves the row only while `pending_verification` (a `needs_attention` one whose row still stands never landed). Known limit: the lock pool (5 per process per database) is shared by all tenants; exhaustion answers `DOC_BUSY`, which the caller retries.
- **Stuck link reconcile (plan 71, lane PO-LINK-STUCK-RECONCILE-B).** (a) The split is judged by the ONE link comparator (`payloads.verify_link_doc`): header = every field read before the write except the vendor-derived ones (`vendor_derived_header`: totals, tax, TaxEntityID, stamps; the Remark mirror as before), the kept row keeps item, unit, location and price; a non-verifying split is read once more after `SPLIT_REREAD_WAIT_SECONDS`. (b) A parked split is re-verified by Resume and by a same-key resend (`_resume_split`): the link PUT is never sent again, the only write is the one restore; "absent" is trusted only `LOOKUP_SETTLE_SECONDS` after the write; a write-gate refusal there is logged `guard_refused` like the primitive path. (c) `VENDOR_TIMEOUT` is classified on the RAW vendor body (`primitives.is_vendor_timeout`: all lines of `ExceptionMessage` / `Message` along the `InnerException` chain, SqlException number -2, class names containing sql / win32 / timeout), never on the redacted text; a lock wait stays a refusal on the batches, a split with a bare vendor error is parked. A timed-out single-document primitive is looked up on a same-key resend like a pending one (`_look_up_primitive`). (d) `close_superseded` (route `POST /write-operations/{id}/close-superseded`): link operations only (`_resumable_op`, the check Resume uses), only once the write is settled (`_write_settled`; an operation with no owned actions uses its own `updated_at`), conditional on the parked status AND the `updated_at` read (a resume that finished in between is not overwritten), no AutoCount call at all. It stores `closedAt`, `closedBy` and `supersededTie` (intended tie + known rows + the earlier answer). Guard: `_ss_ties` / `link_results_on_doc` include `refused` + `SUPERSEDED` rows through `supersededTie`, so a later new-key split of the same PO row to the same SO line and qty is `ROW_ALREADY_LINKED` while that tied row stands; `pending_link_qty` counts the tie for `SUPERSEDED_COUNT_SECONDS` (1 h). `_nothing_landed`, `_create_resend`, `_look_up_primitive` never release or re-run a `SUPERSEDED` row. Operators close only a press they have checked.
