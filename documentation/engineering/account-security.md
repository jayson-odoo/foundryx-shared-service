### Account security - change-email ceremony + My Account (LIVE since sprint-2/04)
Dual-confirmation email change (closes BL-008) + BL-005 login error classes - plan: `documentation/plans/sprint-2/04-account-security.md`.
- **Self-service = dual confirmation**: `/account` → password re-entry (fresh proof; wrong password = **400 not 401** - the api-client signs out on any 401-with-token - and is throttle-counted like a login fail, but success deliberately does NOT `reset_email` the login bucket) → approve link to the OLD mailbox → verify link to the NEW mailbox → `users.email` flips ONLY at verify (sets `email_verified_at`). `email_change_requests` table (PENDING_OLD→PENDING_NEW→COMPLETED|CANCELLED; ONE TTL `email_change_token_ttl_minutes` for the whole request; tokens = plan-10 plaintext-capability convention; new_token exists only after approve). Re-request/cancel supersedes outstanding rows. **Each ceremony step = ONE commit** (repos take `commit=False`, the outbox enqueue owns the transaction) - never split a step across commits, a crash strands the ceremony. Uniqueness: request stays UNIFORM (no enumeration), verify re-checks **with `include_trashed=True`** (uniqueness guards must mirror `uq_users_tenant_email`'s full scope or the flush 500s) → 409 + IntegrityError backstop inside the same try.
- **Endpoints**: `POST/GET/DELETE /me/change-email` (perm-free self-scope) + public `POST /auth/{approve,verify}-email-change` (failed redeems pump the IP throttle). Frontend: `/account` (My Account - profile card, ceremony dialog → pending banner, reset-password link; future home for avatar/timezone) + public `(auth)` redeem pages - redeem fires on EXPLICIT CLICK only (mail-scanner prefetch must not burn single-use tokens). Reference DX: `services/email-change-service` trio + `hooks/use-email-change{,-redeem}`.
- **Admin instant path**: `PATCH /users/{id}` accepts `email` - actor from `get_actor_user_id` (real admin under impersonation), guard FAILS CLOSED (no/self actor → 409 "use My Account"), clears `email_verified_at` (unproven mailbox), notifies BOTH addresses. User form: email editable only for OTHERS.
- **Session staleness**: verify runs in the NEW mailbox's browser context - the original session catches up via `hooks/use-session-email-sync` on `/account` (probes `/auth/me`, calls NextAuth `update()` ONLY on drift; a bare update-on-mount loops the protected layout's loading state). The jwt `update` branch re-pulls email/name/avatar too.
- **BL-005**: `authorize()` maps network failure/5xx → "Service temporarily unavailable - please try again." (JSON error channel); 401 keeps the uniform credentials message, 403/429 detail passes through.
- **Shared primitives born here**: `lib/service-errors.ts` (ONE InvalidTokenError/RateLimitError identity - services re-export), `e2e/helpers/mailbox.ts` (maildir readers, `containing` discriminator - multi-mail flows race the dispatcher otherwise; pair with `timeout: 120_000` on serial mail specs), header mega-menu now renders on EVERY page (the Metronic `/account` Breadcrumb special-case is gone). Follow-ups: BL-069 (E2E self-cleaning fixtures - purge `e2e-%` tenants in teardown + refresh demo CSW), BL-070 (generalize single-use-token/TokenRedeemPage/throttle-guard).
