### Rule Engine (LIVE since sprint-2/02 - the second platform engine)
Facts + operators + JSON condition trees → boolean, evaluated **in-memory** (sibling of `filter_translator`, which stays SQL-only) - plan: `documentation/plans/sprint-2/02-rule-engine.md`. First consumer = conditional status-transition edges; Workflow engine (BL-025) consumes `evaluate()` next.
- **Rule = property, not entity (D1)**: NO `rules` table - each consumer stores its own camelCase tree in its own JSON column (`status_transitions.conditions_json`; NULL = unconditional). **JSON columns: always `JSON(none_as_null=True)`** - the default stores Python None as JSON `null`, which passes `IS NOT NULL` filters (a cleared edge ghosted on the Rules page as "Always allowed" until fixed).
- **Package `app/rule_engine/`** (mirrors `app/status_engine/`): `evaluator.py` - pure `evaluate(tree, facts)`, **fail closed uniformly (D5)** incl. negative ops + cross-fact RHS (`valueKind:"fact"`, scalar ops only, D4); `failed_conditions` is **combinator-aware** (only leaves that actually block - not satisfied-OR siblings); `collect_fact_keys` for needed-keys resolution; depth cap imported from `filter_translator.MAX_GROUP_DEPTH` (ONE constant). Date-only `between` END bound = inclusive whole day. `schemas.py validate_tree(tree, sources)` = the save-time 422 gate (unknown fact, op-for-type, cross-fact type mismatch, **blank/non-numeric values** - a blank bound would save clean then fail closed forever). `prose.py` (operator phrases - keep in sync with `types/rules.ts RULE_OPERATORS`, comments cross-reference). `registry.py` - **whitelist fact sources, never auto-expose schema (D7)**: `infer_facts(Model, [attrs])` infers type/label/resolver from columns; computed/enum/list facts = explicit `FactDef` (options may be `callable(db, user)` for tenant-scoped lists). Core registers `actor` (User) + `record:tenant`; a module's adoption = `register_fact_source("record:<entity>", …)`. `resolve_facts(db, objects, only_keys=)` - pass `collect_fact_keys` output so computed facts (userCount COUNT) aren't paid for rules that don't read them. `sites.py` - rule-site registry behind `GET /rules` (observability, `rules.read`); listers return **data (`site`+`target`), never frontend URLs** - the frontend maps to its own deep-link route.
- **Status-engine integration**: `transition()` re-checks at fire → `TransitionConditionsNotMet` 409 listing the failed conditions via prose; `available_transitions()` hides failing edges (like role-blocks); **generic `status_machine.fireable_edge_ids(db, entity_type, records, actor)`** = per-record fireable ids for LIST surfaces, batched (one edge query/page, None while no conditioned edge exists) - adopting entities reuse it, never re-implement per-row loops. `actor=None` ⇒ actor.* facts fail closed BY DESIGN (system contexts can't fire actor-conditioned edges).
- **Endpoints**: `GET /rule-facts?sources=` (authenticated-only, D13 - builders need it; writes ride each consumer's own perm) + `GET /rules` (`rules.read`, core CSV).
- **Frontend**: `components/platform/rule-builder/` `<RuleBuilder facts value onChange>` - source-grouped fact picker, per-type operators, literal⇄fact toggle, nested groups, stale-fact chips; mount-initialized (remount via key to load a new tree). Edge drawer Conditions section consumes it; `components/platform/rule-engine/` = shared `RulesPage` + list config. `lazy_once` (`app/lazy_registry.py`) replaces hand-rolled `_ensure_core` guards. Shared client CSV escaping = `lib/csv.ts`.
- **Tests**: `tests/test_rule_engine.py` (evaluator matrix → API; `record:ticket` fact-source registration = the module-adoption reference). E2E `e2e/rule-engine.spec.ts` (parallel-safe condition shape: `Slug is not <own-e2e-slug>` passes for every other record).
