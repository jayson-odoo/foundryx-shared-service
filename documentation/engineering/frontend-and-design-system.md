# Frontend layering, Resource shell, design system, canvas principles, backend layering

> Moved verbatim from `CLAUDE.md` on 2026-09-05 (slim-index restructure). The rules here still bind; `PRINCIPLES.md` governs on conflict. Update THIS file when the engine changes.

### Frontend layering (enforced)
`UI component → custom hook → service → lib/api-client → FastAPI`. UI components receive data via props/hooks only and never call `fetch`/axios directly. Standards (evolved in sprint-1/02): **rich entities use the full-page Resource form** (`components/platform/resource-form`, read + global Edit toggle, record-nav, tabs) - modals reserved for trivial entities; **soft-trash + restore** (not hard-delete) for users. The reusable list/form shell lives in `components/platform/{resource-list,resource-form,resource-actions,multi-select,overflow-pills,status-badge}` and is config-driven (see `documentation/plans/sprint-1/02-user-management.md`).
- Key dirs (root-level, no `src/`): `app/` (routes - `(auth)`, `(protected)`), `components/ui/` (~78 shadcn/ReUI primitives), `components/auth/` (shared auth pieces - `AuthBrandPanel`, `AuthFooter`), `hooks/`, `services/`, `lib/`, `config/`, `providers/`.
- Path alias `@/` → repo root (see `components.json` aliases).

### Resource design language (the reuse contract - sprint-1/02)
Every list/form in the system is built on the **config-driven Resource shell** in `components/platform/` - do **not** hand-roll tables/forms. **Users is the reference implementation** (`app/(protected)/user-management/users/`); clone its shape for new entities.
- **New entity = a config + a few custom cells.** Write `useXListConfig()` → `ResourceListConfig` (columns, `viewKey`, `rowHref`, `fetcher`, `exporter`, `filterFields`, `exportColumns`, `actions`) and `useXForm()` → `ResourceFormConfig` (breadcrumb, tabs, `onSave`, `recordNav`). Wire `<ResourceList config>` / `<Form {...form}><ResourceForm config></Form>`.
- **List invariants:** full-width (`Container width="fluid"`), server-side sort/filter/search/paginate via `useResourceList`, per-user column prefs by `view_key` (`useViewPreferences` → backend), fixed columns set `meta.reorderable=false` (stay pinned), multi-value cells use `OverflowPills` (width-aware `+N`), pick-many fields/filters use `MultiSelect` (search + select-all + pills), status via `StatusBadge` + a per-entity registry, one **action registry** surfaced in row `…` / bulk dropdown / form `…`. The Active|Trashed segmented control relabels per entity via `statusViewLabels` (tenants use Active|Archived); selected segment = filled primary; **row selection clears on view switch** (selection belongs to its view - don't undo this, it fixed silent cross-view exports).
- **Card view (sprint-3):** a config `cardRender` (returns the card BODY) + `defaultView` light up a **card/list view toggle** (Grid/List icons), persisted per user per `viewKey` in localStorage. The shell wraps each card with the selection checkbox + the row `…` action menu; the card grid reuses the SAME data/search/filter/segment/pagination/bulk as the table (Columns + column-DnD are list-only). A config `rowHref` of `'#'`/`''` opts a list out of row/card navigation (no detail page). First adopter = the App Store (card default).
- **Form invariants:** read by default + **global Edit toggle** (single PATCH, dirty-guard), icon tabs, circular `N / M` record-nav carried in the URL (`?ctx=&i=`), required fields marked with `*` via `FormRow`.
- **Backend per entity:** Pydantic schemas expose **camelCase** (`Field(validation_alias="snake_case")` + `from_attributes`); recursive filter goes through a **whitelisted** translator (never arbitrary columns); every repository query is tenant-scoped.

### Design system (Foundryx brand)
- **Tokens:** `css/foundryx-tokens.css` - imported AFTER `config.reui.css` so Foundryx values win over Metronic defaults. Primary brand = **orange `#FF5A00`** (`--primary`). Source of truth = `documentation/ui_ux/FoundryX-{Light,Dark}.TokensStudio.json` (Figma Tokens Studio export; filenames are a sanctioned legacy exception).
- **Fonts:** Poppins (display - `font-heading` utility) + Inter (body, default `font-sans`), both via `next/font/google` in `app/layout.tsx`.
- **Figma → code:** designs pulled via the Figma REST API (`/v1/files/<key>/nodes`, `/v1/images` for PNG/SVG export). The Metronic file key is `fPQB8IuZ76vLaHOjMQqsfA`; brand assets land in `public/media/foundryx/`. Build UI from the Figma frame, not guesswork.
- Governance reminder: Metronic utility classes only - **no `<style>` tags, no raw CSS** (the old `branded.tsx` `<style>` block was removed for this reason).
- **Responsive - mobile AND desktop (user mandate):** every screen must look good and be usable at **both desktop and mobile** widths (no horizontal scroll, no clipped/overlapping controls, drawers/dialogs/tables/canvas all reflow). Build mobile-first with Tailwind responsive prefixes (`sm:`/`md:`/`lg:`); side-by-side panels (palette · canvas · drawer; list ⇄ detail two-panes) must stack or collapse on small screens. **Verification is required, not optional:** check each new/changed surface at a desktop viewport (~1280px+) AND a mobile viewport (~375px) - in the retired scripted runner this was `page.setViewportSize(...)` / a mobile project, or screenshot both. A feature isn't done until it's confirmed at both sizes. (The workflow canvas now stacks its palette·canvas·drawer columns on mobile + scrolls each panel to the canvas height - done in slice 09.)
- **Foolproof-UI / no-inline-instructions rule (user mandate):** the UI must be self-evident from its controls, labels, and layout alone - **never add instructional/teaching/hint copy on the screen** ("Click or drag a node onto the canvas", "Connect a node's bottom handle…", field captions explaining mechanics like "available as trigger.input.*"). It clutters the surface and a well-designed UI shouldn't need to teach. Allowed: concise field **labels**, a node/entity's one-line **description** (identifies *what* it is, not *how to use* it), and short empty-state status ("Select a node to inspect"). NOT allowed: procedural how-to text. Proper onboarding = a real **guided product tour** (BL-085), not sprinkled hints.
  - **Only offer valid options; warn on missing prerequisites (user mandate, learned plan-09):** a picker must surface only choices that will actually work - the `entity.update` field picker lists ONLY server-writable fields (not every record field), the status-change entity picker lists ONLY status-engine entities. A node that needs a resource the workspace lacks shows a **warning** (e.g. email/storage action with no connection configured), never a silent later failure. Foolproof = the UI can't be configured into a guaranteed runtime error.
  - **Don't auto-derive ambiguous actions (user mandate, learned plan-09):** auto-connecting a new canvas node "from the nearest leaf" felt helpful but forced WRONG edges (an action meant for an IF false-branch wired to the true-branch node). When the right target is ambiguous, do nothing and let the user choose. Convenience that guesses wrong is worse than an explicit step.
- **Canvas-editor interaction principles (workflow/status editors, learned plan-08/09):** these are the baseline interactions any node-graph editor must have, and the lessons that hardened them:
  - **Long catalogs collapse + search, never flat-list:** the node palette is collapsed-by-default sections with counts + a search box (a flat list grows unusable as the catalog grows). Same for in-canvas menus - a "Replace node" list became a compact two-view menu (Replace ▸ → searchable scrollable submenu), not an inline list.
  - **Every dropdown is a searchable `SearchSelect`** (reinforces the BL-062 mandate) - `select`/`template` fields, entity/status/field pickers, even 2-option toggles. Multi-value pickers get `MultiSelect` (search + select-all). No bare shadcn `<Select>`.
  - **Side panels match the canvas height + scroll internally** (`lg:h-[calc(100vh-…)] overflow-y-auto`) - they must NOT stretch the page; long palettes/drawers scroll within their own bound. On mobile the palette·canvas·drawer columns stack (`flex-col lg:flex-row`).
  - **Floating menus clamp into the viewport** - a cursor-anchored context menu near an edge measures itself (`useLayoutEffect` on the ref) and flips up/left to fit; never let a popup truncate off-screen.
  - **Standard node interactions:** right-click → context menu (replace / delete), keyboard **Delete/Backspace** removes the selected node - but the delete guard must skip when focus is on ANY interactive control (`button, [role="combobox"], …`, not just `input/textarea`), since SearchSelect/dropdown triggers are buttons and a reflexive Backspace would otherwise destroy a node mid-config.
  - **Node identity = unique editable names + distance hints (n8n):** two same-type nodes need a unique, user-editable display name; the dynamic-content picker groups by that name + an "N nodes back" hint. Refs stay **id-based** (`nodes.<id>.<out>`) so a rename never breaks an expression. Duplicate names block publish (front + backend parity).
  - **Quick-replace in place:** swap a node's catalog type (same kind) keeping its id/position/name/edges (resets config to the new type's defaults) - from both the drawer's type SearchSelect and the context menu.

### Backend layering (enforced - Service-Repository pattern)
1. **Router** (`app/api/v1/`) - HTTP validation (Pydantic) + responses only. No DB logic, no raw SQL.
2. **Service** - business logic, workflow triggers, rule-engine evaluation.
3. **Repository** - pure SQLAlchemy queries.

Auth is unified: protected endpoints use `Depends(get_current_user)` (`app/dependencies.py`). Modules must not implement their own JWT/session logic. Current layout: `config.py`, `database.py`, `security.py`, `dependencies.py`, `main.py`, `models/`, `schemas/`, `api/v1/`, `services/`, `repositories/`. Service + Repository layers are populated as domain features land.
