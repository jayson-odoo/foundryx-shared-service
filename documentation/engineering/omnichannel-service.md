### First real module: `omnichannel` (WhatsApp BSP, sprint-1/04-06; plans 04+05 DONE on main)
The omnichannel BSP is the **first App Store module** and the reference for the contract. Backend lives at `service_backend/modules/omnichannel/` (own `OmniBase` metadata + schema `app_omnichannel`, `manifest.json`, `permissions/permissions.csv`, adapters/repositories/services/routers); frontend under `service_frontend/app/(protected)/omnichannel/` + `components/platform/channel-connect-wizard/`.
- **Loading:** via the App Store loader above (manifest-driven since plan 08 - the hardcoded wiring is gone). Per-tenant seeding lives in `install_tenant` (statuses + default "General" workspace); `tenant_has_data` marks pre-App-Store tenants for backfill.
- **Phase-B deviations from the plan (tracked):** schema/tables via `create_all` not per-module Alembic (BL-029); core FKs stored as plain indexed columns, not DB-level cross-schema FKs (BL-030).
- **Onboarding = Embedded Signup only** (Foundryx = Meta Tech Provider). `WhatsAppCloudAdapter` is dev-safe: with `META_APP_ID`/`META_APP_SECRET` unset it stubs the code-exchange so the flow runs locally with no Meta app. Channel `credentials_json` is **Fernet-encrypted** (`OMNICHANNEL_FERNET_KEY` - set in prod, BL-031). There is ALSO a **manual connect** path (wizard → "Set up manually": paste a System User token + Phone Number ID) - both paths subscribe the WABA to the app's webhooks (`subscribed_apps`).
- **Message processing is LIVE (plan 05, on main).** Conversations API (`/omnichannel/contacts` - threads/messages/PATCH, field-gated RBAC assign-vs-reply), CSW-enforced outbound (free-form ≤24h else approved-template-only, reply threading via `context.message_id`), inbound webhook pipeline (fast-ACK → Celery → parse/idempotency-by-wamid/contact-stitch/CSW-reopen/forward-only-receipts), Redis pub/sub + WS realtime, `StorageService` media, inbox UI (`ConversationDrawer`). **Two search layers:** list search = name/phone/**message-body** (server, EXISTS subquery); in-thread search = client-side highlight + match nav. **Verified end-to-end against real WhatsApp traffic** - inbound to a connected number auto-creates the contact + pushes the bubble live. **Webhook go-live:** Meta config needs ONE public callback URL (dev = `cloudflared tunnel --url http://localhost:8001`) → `…/omnichannel/webhooks/{channel_id}`, verify-token `META_WEBHOOK_VERIFY_TOKEN`, subscribe the `messages` field. Dev-mode Meta apps only deliver outbound to allowlisted recipient numbers (API Setup → Manage phone number list).
- **Module env vars** - backend (`Settings`): `META_APP_ID`, `META_APP_SECRET`, `META_GRAPH_VERSION`, `META_ES_CONFIG_ID`, `OMNICHANNEL_FERNET_KEY`. Frontend (`.env.local`, public): `NEXT_PUBLIC_META_APP_ID`, `NEXT_PUBLIC_META_ES_CONFIG_ID`, `NEXT_PUBLIC_META_GRAPH_VERSION`.
- **Embedded Signup is real-or-simulated by env:** the wizard launches Meta's JS SDK when `NEXT_PUBLIC_META_APP_ID` + `NEXT_PUBLIC_META_ES_CONFIG_ID` are set; otherwise it falls back to a simulated popup (so dev + tests need no Meta app). Go-live runbook: `documentation/plans/sprint-1/04-omnichannel-embedded-signup-runbook.md`.
- **Tests** use SQLite with `schema_translate_map={app_omnichannel: None}` (conftest creates `OmniBase` tables, runs `bootstrap_modules(engine, db)`, then installs omnichannel for the default tenant via `AppStoreService.install` - the real store path, which also grants the module keys to the test Admin).

#### WABA management - Config/Profile + Templates (plans 06+07, MERGED to main)
Surfaces Meta `whatsapp_business_management` as **tabs on the channel ResourceForm** (Configuration · Templates · Profile) so a tenant manages their WABA from inside Foundryx. **Meta is system-of-record; Foundryx mirrors locally + explicit Sync; editable fields are write-through** (POST Meta → refresh local on success). Plans `sprint-3/06-omnichannel-waba-config-profile.md` (Slice A, Config+Profile) + `07-omnichannel-templates.md` (Slice B1, templates). Balance/Calls = backlog BL-106/107; profile photo upload = BL-108 (reuses the template `upload_resumable` helper). All in `app_omnichannel` (idempotent `ADD COLUMN IF NOT EXISTS`, module CSV - no core pollution).
- **Dev-safe is `_is_dev` = `creds.get("dev") OR not settings.meta_app_id`** - the adapter dev-stubs every Meta call when no Meta app is configured OR the channel carries dev creds. **E2E needs a DEV-cred channel** (`chn-demo`, seeded by `seed_demo_conversations`): with `META_APP_ID` SET in `.env`, a *real* channel (e.g. a live-onboarded number) hits Graph for real - only the dev-cred channel stays stubbed. If the demo channel is missing from the local list it was disconnected (`is_trashed=true`); restore it rather than retargeting the spec.
- **Configuration tab** (`channel-form-fields.tsx`, merges old General+Connection): editable name/workspace/active + read-only synced identity block (display number, verified name, business account, phone/WABA id) + **Sync** (pull phone+WABA details, stamp `last_verified_at`) + Test Connection. **Profile tab** (`channel-profile-tab.tsx`): write-through `about/address/description/email/vertical(SearchSelect)/website1/website2` + read-only photo + Sync Profile. ONE combined RHF form drives both tabs (single global Edit toggle); Sync Profile must `form.reset` the inputs too (not just the read view) or a later Edit shows stale values and Save clobbers the fresh sync. **Save write-through nuance (review-hardened): a CLEARED field is sent to Meta as `""` (not omitted) so Graph clears it** - omitting leaves Meta's old value while nulling locally (mirror divergence); a Meta `SendError` → **502, local mirror untouched** (atomicity). Vertical whitelist parity = `verticals.py` ↔ `lib/whatsapp-verticals.ts`.
- **Templates = local-draft lifecycle, NOT the status engine** (Meta owns the fixed enum + drives transitions via webhook; an editable graph for Meta's review states would be a foolproof-UI violation). `LOCAL_DRAFT→PENDING→APPROVED/REJECTED/PAUSED/DISABLED`, rendered via a frontend **StatusBadge registry** (`template-status.ts`; display label is "Draft", key stays `LOCAL_DRAFT`). **Single canonical store = Meta-shape `components_json`**; the friendly `WaTemplateDoc` is derived via `to/from_meta_components` - ONE bidirectional transform, parity-pinned `template_schemas.py` ↔ `lib/whatsapp-template.ts` by a golden test (SEC-5). `TemplateManagementService`: list/save_draft/submit/edit(status-gated: draft free / approved→re-submit PENDING / pending+disabled 409)/delete(draft local, synced Meta DELETE)/sync(dev promotes PENDING→APPROVED)/**`apply_webhook_event`** (idempotent, malformed-safe never crashes the inbound pipeline, status normalised to the local set). Media-header sample → `storage_for_tenant` key → on submit `upload_resumable` → header handle. Two-pane builder route (`[id]/templates/{new,[templateId]}`) = component editor ‖ live `WaBubblePreview`; AlertDialog dirty-guard; field-level 422 mapping. **Validation rules (review-hardened, both layers): body/header `{{n}}` must be SEQUENTIAL `{{1}}..{{N}}`** (example arrays are positional), and a var-less TEXT header must NOT emit a stale `example` (Meta format rejection).
- **NAME-COLLISION LESSON (load-bearing):** the core **Template Engine** (sprint-2/07) already owns the permission keys `templates.read`/`templates.manage` AND the frontend service `template-service.*`. The omnichannel module had to namespace its own: perms **`wa_templates.read`/`wa_templates.manage`**, service **`whatsapp-template-service.*`**. Before adding a module permission resource or a `*-service.ts`, grep core for the same name - `sync_permissions` is delete-by-module on the GLOBAL `permissions.key`, so a duplicate key throws a UNIQUE violation at bootstrap.
- **Embedded ResourceList in a tab + bulk actions**: the Templates tab embeds `<ResourceList>` (remount via a `key` to reload after Sync; row actions reload via the table-meta `reload`). For bulk actions + a left checkbox column, add the `select` column (`DataGridTableRowSelectAll`/`DataGridTableRowSelect`) and `surfaces:{row,bulk}` on the actions - same shape as the Users/Channels lists. A `StatusBadge` inside a `flex flex-col` cell stretches full-width → wrap with `items-start`.
- **Fixed-height scroll-shell gotcha (the inbox + any list⇄detail pane):** a two-pane shell that must fill a fixed height and scroll INTERNALLY needs (a) NOT `flex-1` on the shell if its flex parent is unbounded - `flex-grow` resolves against content and balloons the element past an explicit `height`; and (b) `grid-rows-[minmax(0,1fr)]` on a CSS grid, else the implicit row `auto`-sizes to content and the cells overflow even when the container is height-bounded. The fix made the omnichannel inbox columns align + the conversation scroll. When debugging a Radix `ScrollArea`, measure `[data-radix-scroll-area-viewport]` (the real scroller) - `viewport.parentElement` of the content is a `display:table` wrapper sized to content, a misleading read.
- **Cross-branch alembic**: the live DB's `alembic_version` can be pinned to a migration a feature branch PREDATES (e.g. plan-05's `e5f6a7b8c9d0` while on the plan-07 branch cut before it) → `bootstrap_db`/`alembic upgrade` fails "Can't locate revision". The schema is already ahead, so bypass alembic: run `bootstrap_modules(engine, db)` (module CSV sync + idempotent column ALTERs) + `tenant_admin_grant` directly to refresh perms/columns. Merging the branch onto main (which HAS the migration) resolves it cleanly.

#### Public consumer gateway - respond.io response parity (MERGED to main, `sprint-4/omnichannel-respondio-parity`)
The public gateway (`/api/v1/omnichannel/*`, workspace-API-key auth via `get_api_workspace`, NOT session JWT) mirrors respond.io's **response shapes** so external consumers can use it like respond.io. The endpoints already existed (plan sprint-1/01 Slice 3); this pass reshaped the wire + added filters. **This is a BREAKING wire change** to those endpoints - but only external API-key clients consume them (our own inbox uses `/omnichannel/contacts`, a different mount).
- **⚠️ THE CONSUMER GUIDE IS PART OF THE CONTRACT - change the wire, change the guide, same commit.** `documentation/omnichannel/consumer-integration-guide.md` (also published at `doc.foundryx.my`) is what external integrators build against. The 07-11 reshape shipped WITHOUT updating it, and the note above ("only external API-key clients consume them") was the exact error: **external API-key clients ARE the guide's audience.** A consumer (Ecohub) built to the published §6/§9, got `200`s with a different shape, and silently rendered empty conversations for weeks - no error anywhere. Reconciled 2026-08-09. **The guide was IN the repo the whole time** - being in git did not save us, because the reshape commit simply didn't touch it and no reviewer asked why. So the rule is a review-gate rule, not a file-location rule: (a) a diff touching `Rio*` schemas or `api_v1.py` **without** a corresponding guide diff is an automatic review question - the reviewer must demand it (CI guard = BL-SS-022); (b) never justify a breaking gateway change with "only external clients consume it"; (c) `tests/test_omnichannel_api_gateway.py` carries **contract-drift regressions** (timestamp / cswExpiresAt / payload / caption-split) - they exist to fail loudly, don't relax them. Keep ONE guide file - a second copy at another path is a second contract, and the stale one is the one the next integrator finds.
- **Gateway read shapes must stay LOSSLESS vs the internal `MessageItem`/`ThreadItem`.** The 07-11 reshape dropped `createdAt` (⇒ inbound messages had NO time at all, since `status[]` is receipt-driven and inbound never gets one), `cswExpiresAt` (⇒ the 24h free-form window was undetectable - consumers had to force template-only sends or provoke a `409`), plus `payload` (interactive buttons / location coords flattened to a lossy text summary), `mediaSize`, `reactions`, `replyTo`. All restored 2026-08-09: `RioMessageItem.timestamp` (epoch, **inbound AND outbound**), `RioContactItem.cswExpiresAt` (ISO-Z - FX extension, so house convention, not respond.io epoch), `message.payload`/`message.size`, `reactions[]`, `replyTo`. Renaming for parity is fine; **dropping a field the internal shape carries is not** - a consumer has no other source for it.
- **`?format=` is the shape switch; GUIDE is the DEFAULT (2026-08-09).** `/api/v1` reads return `MessageItem`/`ThreadItem` in the documented envelopes (`{contactId,data,nextBefore}` / `{data,total,page,pageSize}`); `?format=rio` returns the respond.io shapes. Both are derived from the SAME internal objects (`conversation_service.message_items`/`thread_item`) - never build a second data path per format or they drift. An unknown format is a typed 422, never a silent fallback (a typo must not hand a consumer the other shape to mis-parse). Adding a field? Add it to the internal shape; the Rio mapper reads from there.
- **Webhook registration is self-serve on `/api/v1` (BL-SS-025).** A workspace key manages its own callbacks. `WebhookService._get` is **tenant-scoped only** - use `get_for_workspace`/`list_for_workspace`, which re-check `workspace_id` and raise the SAME `WebhookNotFound` as a miss. The guard lives in the SERVICE, not the router, so a future non-HTTP caller inherits it. Per-channel cap `MAX_ENDPOINTS_PER_CHANNEL` (every inbound event fans out to all endpoints).
- **An externally-supplied callback URL is re-validated before EVERY delivery** (`assert_deliverable` in `webhook_delivery._deliver`). Registration-time validation alone is not enough: DNS can be re-pointed afterwards, and since any API-key holder can set the URL, a fail-open registration would aim the delivery worker at an internal address (blind SSRF pivot). Registration stays lenient on unresolvable hosts on purpose - strict-at-registration makes it depend on live DNS and breaks offline CI; the per-attempt check is the authoritative one.
- **Cross-tenant leak class, again (2026-08-09):** `conversation_service._user_names`/`_channel_types` resolved a STORED user/channel id with NO tenant filter, and resolve to a name/EMAIL rendered to the caller. Latent while only the inbox used them; flipping the gateway default onto that path put it on a key-authed public surface. Every stored-id resolution takes `tenant_id` - the polymorphic-target_id rule is not optional on read paths.
- **Two shapes, ONE data path**: the `Rio*` renderings are derived from the same `ThreadItem`/`MessageItem` objects the default returns (`conversation_service.message_items`/`thread_item`) - never build a second per-format query path, or they drift again. Webhooks + comment-create always use the default shape, so one internal type covers reads and webhooks alike.
- **A media message's body is its caption, exposed ONCE** - `message.caption`, with `message.text` null (populating both read as a duplicated body). An internal note (`sender.source == "system"`) still reports `traffic: "outgoing"` - `sender.source` is the discriminator; documented rather than re-enumerated, since `traffic` is respond.io's two-value field.
- **respond.io parity schemas are plain `pydantic.BaseModel`, NOT `ApiModel`** (`schemas.py` `Rio*` classes) - deliberate: `ApiModel`'s camelCase-alias + `Z`-datetime serializer would fight respond.io's exact field names. Parity needs snake_case where they use it (`custom_fields`, `created_at`), **epoch-second int timestamps** (`_epoch(dt)` off the aware-UTC `UTCDateTime` columns), and a `{items, pagination:{next,previous}}` envelope. When a wire contract must match an EXTERNAL spec's exact field names/types, bypass `ApiModel` with a dedicated BaseModel family (don't fight the house serializer).
- **Our ids are UUID strings; respond.io's are int64** - `id`/`messageId` stay strings (documented, unavoidable deviation - can't fabricate stable ints). Fields we don't model (contact `language`/`countryCode`/`tags`/`lifecycle`/`isBlocked`, and `priority` - respond.io has no contact-priority field) emit `null`/`[]`/`false`; the value still writes server-side (PATCH), it's just not echoed in the parity shape.
- **Signed, clickable media URLs (the security-sensitive bit).** Public message `message.url` is now an ABSOLUTE, HMAC-signed, time-limited link (`{public_base_url}/omnichannel/media/{id}?exp=&sig=`, `security.py signed_media_url`/`verify_media_sig`/`_media_sig` - HMAC-SHA256 over `f"{id}:{exp}"` keyed by `settings.jwt_secret`, TTL `media_signed_url_ttl_seconds` default 3600). The media route (`routers/media.py`) accepts `exp`+`sig` → verifies → serves with **NO Authorization header** (the signature IS the authz; opens on a raw browser click, the whole point). Rules that made it safe: **the signature binds the exact message id** so it can't be re-pointed; **`hmac.compare_digest`** constant-time; **expiry checked before compare**; the unscoped `ContactRepository.get_message_global` is reachable **ONLY after** a passing verify (never from a normal request path - that stays tenant-scoped `get_message`). The internal inbox `media_url_wire` (relative, Bearer via `apiFetchBlob`) is UNCHANGED - the public mapper builds its own signed URL, it does not repurpose the model property. Capability-URL semantics (bearer-less, replayable within the TTL) are inherent to signed URLs and are the intended design.
- **Two-way keyset message cursor.** `list_messages_recent` gained `after_id` (newer-direction) alongside `before_id` (older); both keyset on `(created_at, id)` and always return oldest→newest. Router builds `pagination.next` (=older, `before=oldest`) + `pagination.previous` (=newer, `after=newest`) as ABSOLUTE URLs via `request.url.replace_query_params(...)` (replaces the whole query - pass EVERY param you want retained; it preserves the path + `{identifier}`). Known v1 imperfection (accepted): after a partial forward page `next` is `None` even though older history exists (gated on `len==limit`).
- **Template filters**: `GET /templates` gained `channelId` (default = the workspace's active channel; unknown = 404 `channel_not_found`), `search` (name `ilike`), `category` (Meta category, upper-cased).
- **Tenant-scope stored user ids at USE time (review catch, the polymorphic-target_id rule again):** the assignee display lookup (`_users_by_id`) resolves `contact.assigned_user_id` - filter `User.tenant_id == tenant_id`, never a bare `User.id.in_(ids)`, even though `patch_thread` validates on write. Any mapper that resolves a stored user/role/record id needs the tenant filter as defense-in-depth.
- Tests: `tests/test_omnichannel_api_gateway.py` (existing gateway tests updated to the new shapes + 4 new - signed-media serve+tamper+expiry, two-way cursor, template channel/search/category). Deploy note: a host still 404ing `/api/v1/omnichannel/*` is running a build that predates the gateway slice OR has omnichannel inactive - a code/deploy gap, not a bug.
