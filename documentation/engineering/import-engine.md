### Import engine (LIVE since sprint-3/09, F8 - the 6th core engine, generic bulk import)
A 4th toolbar button (Filters · Export · Import · Columns) on any **opt-in** Resource list, backed by a per-entity `ImporterDef`. Plan `09-import-engine.md`. **Core** (`app/import_engine/`, mirrors form_engine), server-authoritative, two-phase, Celery-decoupled (eager inline in dev).
- **Per-entity `ImporterDef` registry** (`registry.py`, sibling of WorkflowEntity/StatusEntity); `ResourceListConfig.importer = {entityType, writePermission, context?}` → the Import button renders when set + the user holds the entity write perm. `infer_import_columns(model, writable)` seeds `ImportColumn` defaults from the SQLAlchemy columns (mirrors `infer_facts`); the def overrides resolver/options/validators/transform. **Importable columns ⊆ the entity's `entity.update` writable whitelist** (drift-guard test). First target = `user`; EMS adds `profile` + project-scoped `project_participant`.
- **Two-phase, server-authoritative, all-or-nothing** (`service.py`): **Test** (validate, dry-run, zero writes) → **Import** (commit, ONE transaction over the whole valid set). Client does only trivial pre-flight (no validation mirror). `import_jobs` row = source of truth (migration `d5e6f7a8b9c0`). Double-commit guard = atomic status claim. **Strictly set-based**: one batched query per resolver, one match-existence query, bulk DML (a test asserts no per-row explosion).
- **3 modes, `id`-only matching (D5)**: create-only (reject present id) · update-only (id must exist) · upsert. **Updating requires Export-first** (export populates id). Partial update; required enforced create-only.
- **`unique` columns validated against the TABLE at Test, not just in-file** - a value already in the table is a per-row error at validate, never a DB-UNIQUE explosion at commit (learned bug). Case-insensitive, batched, tenant-scoped.
- **Multi-format reader** (`readers.py`): xlsx/xls/csv magic-byte sniff → uniform `list[dict]`; positional header detection (first non-empty row); duplicate headers auto-suffix; openpyxl `read_only/data_only`, capped. **Formula-injection sanitize** every generated cell (template + error file). Caps per-tenant (`import_settings`, fail-fast at upload) - configured at **`/settings/imports`** (`GET/PUT /imports/settings`, gated `imports.read_all`).
- **`trigger_automations` (default OFF)**: ON emits per-row `entity.created` / **`entity.updated`-WITH-a-field-`changes`-diff** after commit → `dispatch_pending` (the internally-committing pattern: emit with `actor_id=` then explicit dispatch - NOT the after-commit drain). Without the changes diff, `entity.field_changed` workflows never fire on import-update (learned). Import-create emits `entity.created` (won't fire a field_changed trigger - that's correct).
- **D17 context** (embedded-list parent scope, e.g. `{project_id}`) + **D18 find-or-create resolver** (existing match → link, no match → create the referenced record in the same txn, NEVER update a shared one) - both consumed by the EMS participant importer.
- **UX (heavily user-iterated post-merge):** the upload **modal** is minimal (Mode · Abort toggle? NO - moved · drop file · one "Download template" link); **template options** (format + which columns) live in a SEPARATE dialog with a **searchable scrollable column checklist** (required locked-in, no pills - scales to many columns). After upload → **ONE page** (`/imports/[jobId]?from=`): map (file header ↔ system column compact on the left) + **Test** + **Import** + inline results/errors (no separate results page; max 2 navigations). **Abort/Trigger toggles live on this page** (chosen at Import; commit endpoint accepts overrides). Successful import → **redirect to `?from=`** (the originating list). Jobs tracked in a dedicated **Imports activity drawer** (header trigger, sibling of Uploads/Downloads - the upload-manager is file-upload-specific, so imports get their own drawer, not the upload drawer). `/imports` = full history list.
- **Export↔import symmetry**: export includes the **`id`** column (backend `_column_value` + `exportColumns`, id-first) so export → edit → re-import(update) round-trips; **the Export button is available while rows are selected** (selection toolbar) so you can export just the selected rows. Apply both to any list that wants the round-trip.
