### Module Platform v2 (LIVE since sprint-3/10, F9 - inter-module deps + capabilities; closes BL-029)
Extends the App Store from isolated leaf modules to an ecosystem. Plan `10-module-platform.md`. `app/module_platform/`.
- **Per-module Alembic (D3, closes BL-029)**: `modules/<name>/alembic/` (own env.py + version table in the module schema, declared in manifest). Orchestrator `run_module_migrations` (in `bootstrap_modules`): version-row → `upgrade head`; legacy tables (create_all) → **`stamp head` (no DDL)**; fresh → `upgrade head`. **Postgres-only - no-op on SQLite tests** (conftest keeps `create_all`). **Create the module schema before alembic's version table** (else "schema does not exist"). omnichannel stamped to a `create_all` baseline; ems starts clean at rev 1.
- **Capability registry (D5)** = the sanctioned cross-module call seam: `register_capability(CapabilityDef{key, version, provider_module, handler})` at BOOT; `resolve_capability(db, tenant_id, key, version) → handler | None` (None when provider not ACTIVE-for-tenant or wrong major = the self-disable signal, NEVER raises for absent). Integer-major exact match; duplicate (key,version) at boot = loud error. Handler `(db, tenant_id, payload)` tenant-scopes internally. omnichannel provides `messaging.send@1`; EMS provides `profile.resolve@1`/`participant.resolve@1`.
- **Soft refs (D6)** = cross-module data WITHOUT FKs: `SoftRef{module, entity_type, id}` resolved via a provider `<entity>.resolve` capability; orphan → None; save-validate + resolve-time tenant-scope (generalizes the polymorphic-target_id rule + BL-030).
- **One `active_modules(db, tenant_id)` filter (D2)**: every registry item carries a `module` tag (`'core'` always visible); `is_visible(module, active)` applied at EVERY catalog consumption point (terminology, importer guard, … new catalogs MUST tag + filter).
- **Public CORS prefixes (plan 34 review round 1)** = the same shape as the capability registry, for the one thing a module can own that core cannot compute: a `"public": true` router whose allowed origins are TENANT data. `register_public_cors_prefix(prefix, provider_module=..., resolver=(path, origin) -> bool)` at BOOT (`modules/<name>/bootstrap.py::register_public_cors`); one owner per prefix, a second claimant is a loud boot error. ONE generic pure-ASGI `PublicCorsMiddleware` (`app/module_platform/public_cors_middleware.py`, registered AFTER `CORSMiddleware` in `app/main.py` so it sits OUTSIDE it) walks the registry: it answers the preflight for a registered prefix - `204`, echoing the origin only when the resolver says yes, never `*` - and strips the stray `Access-Control-Allow-Credentials` that `CORSMiddleware` stamps on before it checks the origin. A request outside every registered prefix is passed straight through with nothing wrapped. **Core holds no module route constants**; a resolver that raises refuses (a preflight must never 500). Today: omnichannel's `/public/omnichannel/webchat/`.
- **Dependencies (D4)**: manifest `requires`/`optional`/`provides`; `resolve_install_order` (topo + cycle = loud error); install requires-guard + cascade-with-consent; **reverse-dep guard on uninstall AND deactivate**. **Errored-module isolation (D8)**: a module failing at boot/migration is marked `errored` + skipped; app + siblings + core continue. Boot hook `register_module_boot` calls each module's `register_capabilities()` + `register_engine_entities()` + `register_public_cors()`.
- Loader/App-Store changes are boot-time + additive. `StoreModuleOut`/`ModuleCard` surface requires/optional/provides/errored/availability. Tests: `tests/test_module_platform.py` (13). **DEFERRED (documented)**: full App-Store-on-Resource-shell rewrite + consumer-module E2E. Report `10-module-platform-test-report.md`.

## Module / App Store governance (`documentation/development_process/EMS_Developer_Governance_Framework.md`)

Every feature is packaged as a self-contained module that the App Store installer certifies. Violations are rejected by the installer.

- **Manifest:** each module has a root `manifest.json` (`module_name`, `version`, `author`, `required_core_version`, entry-point routers).
- **Folder structure:** `/<module>/frontend`, `/<module>/backend/{routers,services,repositories}`, `/<module>/backend/permissions/permissions.csv` (declares the module's RBAC permissions - see RBAC above), `/<module>/alembic`, `manifest.json`.
- **No global pollution:** modules cannot inject into core `main.py` or global stores; hook in via predefined Event Listeners. Frontend modules wrap in an Error Boundary so a crash doesn't take down the EMS dashboard.
- **DB = Schema-Isolated Relational Architecture:** modules create real Postgres tables but inside their own schema (e.g. `CREATE SCHEMA app_commercial;`), never in `public`. Cross-schema linkage via FK into core tables (e.g. `app_commercial.invoices → public.projects(id)`). Never `DROP`/`ALTER`/`TRUNCATE` core `public` tables.
- **Module-isolated migrations (Alembic):** each module tracks its own history in a per-module version table (e.g. `alembic_version_commercial`) so uninstall = drop the module schema + its version table, leaving core clean.
- **No global CSS:** use Metronic utility classes only - no `<style>` tags, no global `.css` overrides.

### App Store (per-tenant module lifecycle - LIVE since sprint-1/08; migrated onto the Resource shell sprint-3)
Each tenant installs/manages modules from **`/app-store`**; the operator does the same for any tenant via the console tenant-detail **Modules tab**. Plan: `documentation/plans/sprint-1/08-app-store.md`.
- **On the Resource shell since `sprint-3/ems-management-ui` (closes sprint-3/10 AC-10-12/13):** one shared `useModuleListConfig(tenantId?)` (`components/platform/app-store/`) drives BOTH storefront (own tenant) and console (operator endpoints). **Card view by default + a card/list toggle**, `All|Installed|Available` segments, and the lifecycle actions in the row + bulk "…" menu (`buildModuleActions` - install/update/deactivate/reactivate/uninstall, state-aware via `isVisible`, typed-confirm uninstall). Storefront cards/rows open a **module detail/form view** (`/app-store/[name]` - read-only facts + the same actions in the form "…"); the console manages inline (no cross-tenant detail route). `ModuleCardBody` is the shared presentational card body. The legacy `ModuleCard`/`ModuleCardGrid` remain only for their unit test.
- **Catalog** = global `modules` table synced at bootstrap from on-disk `modules/*/manifest.json` (display fields `title`/`description`/`icon`; removed dirs are delisted, never deleted). **Per-tenant state** = `tenant_modules` (`status` ACTIVE|INACTIVE + `installed_version`, UNIQUE(tenant, module)).
- **Loader is manifest-driven** (`app/module_loader.py`): `load_modules(app)` dynamic-imports each manifest's routers (`{name, prefix}` objects) and injects **`require_module(<name>)`** at `include_router` - module code stays untouched; routes 403 "Module not installed" unless ACTIVE for the caller's tenant (fresh-from-DB, like `require_permission`). `bootstrap_modules()` (bootstrap_db AND init_db) = catalog sync + every module's global `install()` + transitional backfill (tenants holding pre-App-Store data → ACTIVE rows via the module's optional `tenant_has_data` hook; platform tenant excluded).
- **Module bootstrap contract** (certification requirement, governance doc §1): `install(engine, db)` global-idempotent (schema+tables+perm CSV sync) · `install_tenant(db, tenant_id)` seed · `update_tenant(db, tenant_id, from_version)` data migration · `uninstall_tenant(db, tenant_id)` wipe ONLY that tenant's rows (never drop schema/tables). Grants are the STORE's concern, not the module's.
- **Lifecycle** (one `AppStoreService` behind both route sets): install → ACTIVE @ current code version + `install_tenant` + grant module keys to the tenant's Admin role; deactivate → INACTIVE (routes 403, data kept, grants inert); reactivate instant; update → `update_tenant(from_version)` + re-grant + bump `installed_version` (offered when manifest version > installed); uninstall → typed-confirm (`{confirmName}` must equal module name, 422 otherwise) → wipe tenant rows + revoke module grants from ALL tenant roles + delete state row. Platform tenant can never install (409).
- **APIs**: tenant-side `/app-store/modules` + `/installed` + `/modules/{name}/{install|update|deactivate|reactivate|uninstall}` (gated by `app_store.*` core keys, seeded to tenant Admin); operator `/platform/tenants/{id}/modules[...]` (gated `tenants.manage_modules`, platform guard). Version-gate helper for post-1.0 endpoints: `requires_version(name, ">=X.Y.Z")` (`app/dependencies.py`).
- **Frontend**: `components/platform/app-store/` (`ModuleCard`/`ModuleCardGrid`, shared storefront↔console), `hooks/use-app-store.ts` (`useAppStore(tenantId?)` - omit = own tenant, pass = operator endpoints; `useInstalledModules()` for menu gating). **Menu**: `MenuItem.module: "<name>"` hides tagged entries unless the module is ACTIVE. **Freshness (D7)**: after own-tenant actions the hook refetches + NextAuth `update()` (jwt callback `trigger === 'update'` re-pulls `/auth/me` → fresh `permissions[]`, no re-login).
