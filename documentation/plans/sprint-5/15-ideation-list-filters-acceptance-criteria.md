# 15 - Ideation list filters / sort / columns / vote order, detail upload + status pill, embed promote - acceptance criteria

Owner requests 29 Sep 2026 (screenshots of fe-sorento.foundryx.my/ideas, an idea detail page, and the operator Dashboard > Ideation > Ideas page) plus two scope additions the same day. Lane IDEATION-LIST, branch `crew/ideation-list-filters`.

Surfaces: the OPERATOR page `app/(protected)/ideation/ideas` and the Sorento EMBED iframe `app/embed/ideas` render the SAME `IdeasView` + `useIdeasListConfig` (runtime mode `operator` | `embed`). Every list AC below applies to BOTH unless it names one mode.

## A. Ideas list

- **AC-15-01** Given the ideas list, when I open the filter builder, then a `Status` enum field is offered whose options are the tenant's status LABELS seen on the loaded ideas (key = `status`, label = `statusLabel`), never a hardcoded status union; applying `Status in [Discussed]` shows only ideas whose `status` key matches.
- **AC-15-02** Given the ideas list, when I open the filter builder, then a `Submitter` enum field is offered whose options are the distinct `submitterName` values of the loaded ideas; applying it narrows the rows to that submitter.
- **AC-15-03** Given the ideas list, then a `Submitted` column shows `createdAt` formatted through `useDatetime()` / `lib/datetime.ts` (never `new Date(iso)` directly), in the user's timezone.
- **AC-15-04** Given the ideas list toolbar, when I click `Columns`, then the popover lists every hideable column (Idea, Submitter, Channel, Status, Votes, Submitted, and Product on the operator page) as checkboxes; unticking one hides that column; the shared `DataGridColumnVisibility` and the column-header `Columns` submenu no longer require `accessorFn` to list a column (`enableHiding !== false` is the rule). Other pages whose columns are display-only benefit (BR list, BR ideas tab, idea BRs tab, idea merged tab, autocount pull rows).
- **AC-15-05** Given the ideas list, then every data column (Idea, Submitter, Channel, Product where shown, Status, Votes, Submitted) is sortable from its header (`DataGridColumnHeader`, `enableSorting: true`); clicking toggles asc/desc; the sort is applied by the client-side fetcher (`selectIdeaRows`) with numeric ordering for Votes and date ordering for Submitted (string compare is wrong for both).
- **AC-15-06** Given the ideas list in EMBED mode, then there is NO Product column (the iframe is already product-scoped). Given the OPERATOR page (all products), then the Product column stays (choice noted in the PR).
- **AC-15-07** Given the ideas list, then there is NO drag grip column and NO manual reorder (`rowReorder` removed from the config; the `__drag` column never renders); the board keeps its own drag (unchanged).
- **AC-15-08** Given the ideas list with no sort chosen, then rows are ordered by NET votes (`upvotes - downvotes`) descending, ties by `upvotes` descending, then `createdAt` descending (newest first). The default sort is declared via `config.defaultSort = { id: 'votes', desc: true }` so the Votes header shows the active sort. Rationale: the vote model stores both up and down (`idea_votes.dir`), so net is supported; net is what "most upvoted" means when a downvote exists.
- **AC-15-09** Given the record pager on the idea detail (prev/next), then it walks the SAME order and filter as the list (both call `selectIdeaRows(ideas, query)` with the query's `sort` + `filter`).
- **AC-15-10** Given the operator page, then the page description `The raw idea repository - drag the grip to reprioritise (top = highest).` is gone (no description) and the `Suggest clusters` button / cluster suggestions strip is not rendered on the ideas list (component file stays; the list no longer mounts it).
- **AC-15-11** Given the CSV export, then columns are Idea, Submitter, Channel, Product, Status, Up, Down, Submitted and the rows follow the applied filter + sort.

## B. Idea detail

- **AC-15-12** Given an idea detail page (operator and embed), then the header subtitle is the idea's STATUS pill (`StatusBadge` with the engine label + color, same registry helper as the list) and nothing else - no product name, no submitter, no tier text.
- **AC-15-13** Given the Details tab of an EXISTING idea, then there is no `Product` row (view or edit mode); the saved `productId` is preserved on save (the form still submits the loaded value). Given the create form (`/ideation/ideas/new`), then the Product picker still shows (a new idea needs a product).
- **AC-15-14** Given the Attachments tab, then an upload drop area (`AttachmentDrop`, the existing `useFileUpload` drop-area component) is shown above the list; dropping or picking files uploads each one immediately via `POST /ideation/ideas/{id}/attachments` (multipart `file`), the list refreshes with the new rows, and a toast confirms. The "No attachments" copy no longer instructs (foolproof-UI): empty state = icon + `No attachments` only.
- **AC-15-15** Given an uploaded attachment, then clicking it previews inline (image/video/audio/pdf) by fetching `GET /ideation/ideas/{id}/attachments/{attachmentId}/content` through the api-client as a blob (object URL), never a bare `<img src>` to an auth-gated route; Download uses the same blob. WhatsApp-captured attachments (durable `url`) keep today's direct-URL preview.
- **AC-15-16** Backend upload: sniff-first (`detect_media_mime` from `modules/omnichannel/services/media_pipeline.py` widened by reuse, or an equivalent shared sniff that accepts image/audio/video/pdf/office/text and REJECTS svg/html/executables regardless of declared type), capped read of 25 MB (413 above), 415 on an unverifiable type, stored through `storage_for_tenant(db, tenant_id).save("ideation/ideas/<idea_id>/<attachment_id>", content, mime)`; the row records `storage_key`, `mime`, `size_bytes`, `filename`, `kind` (image|video|audio|file from the sniffed mime), `source_msg_id = "upload:<attachment_id>"` (unique key kept); `url` stays empty for uploads. Served CSP-sandboxed + nosniff + `Cache-Control: private, max-age=300` like `documents._serve_blob`; presigned locations redirect.
- **AC-15-17** Backend: `idea_attachments.storage_key` is declared in `modules/ideation/manifest.json` `storage_locations` (model `IdeaAttachment`, column `storage_key`, tenantColumn `tenant_id`) and `register_engine_entities` registers the manifest-declared locations at boot (omnichannel precedent) so the storage-migration drift test passes and the key rides A->B migrations. New columns land via module Alembic `0013_ideation_attachment_upload` (idempotent `ADD COLUMN IF NOT EXISTS`, Postgres-only, nullable - no backfill needed: existing rows are WhatsApp captures with `url`).
- **AC-15-18** Upload/serve permissions: operator upload gated by `ideation.triage.manage` (the same key that gates `PATCH /ideation/ideas/{id}`); serve gated by `ideation.ideas.view`. Embed upload/serve via `POST|GET /embed/ideas/{id}/attachments[...]` with `require_embed_principal` + `_assert_in_scope` (tenant + product), no operator perm (the token is the boundary, same as embed edit). Cross-tenant: an attachment id from another tenant 404s.
- **AC-15-19** `IdeaAttachmentOut` gains `sizeBytes` (from `size_bytes`) and `contentPath` (the relative serve path, `null` for a URL-backed capture); the FE type `IdeaAttachment.contentPath?: string | null`.

## C. Promote to BR from the embed

- **AC-15-20** Given the Sorento embed detail page (`/embed/ideas/{id}`) or the embed list bulk menu, when a user with `ideation.business_requirements.manage` clicks `Promote to BR`, then `POST /embed/ideas/promote` `{ ideaIds: [...] , title?: string }` creates the draft BR through the SAME `BusinessRequirementService.create` the operator uses (product = the principal's product when scoped, else the ideas' shared product; `actor` = the resolved shared-service user) and returns 201 with the BR detail; the FE toasts `Draft requirement created: <BR title or number>` and stays in the iframe (no BR surface in the embed; the operator path still navigates to the Grill tab, unchanged).
- **AC-15-21** Permission rule = the operator rule, no widening: the embed token's `email` claim (minted from the host assertion) resolves to a shared-service user in the token's tenant (`UserRepository.get_by_email(email, tenant_id)`); `effective_permission_keys(user)` must contain `ideation.business_requirements.manage`, else 403 `{"code":"forbidden"}`. Missing email claim or no matching user = 403. `EmbedTokenPrincipal` carries `email`.
- **AC-15-22** Scope: every idea id must pass `_assert_in_scope` (tenant + product) - an out-of-scope id 404s before any BR is created. Ideas of mixed products 422 (existing service rule).
- **AC-15-23** The operator `POST /ideation/business-requirements` path is unchanged (existing tests stay green); an embed token on the operator route still 401s.
- **AC-15-24** FE: in embed mode the Promote action calls `ideationEmbedService.promoteToBr(ideaIds, title?)` (new optional `IdeaService.promoteToBr?`); `promoteIdeasToBr` takes the runtime mode/service so the list bulk action, the detail gear and any other caller share one path. The embed gear/bulk `Promote to BR` is visible in embed mode (today the `permission` gate hides it because `useCan` has no session there): in embed mode the action is shown ungated and a 403 from the backend is surfaced as a toast `You do not have permission to promote ideas.`

Pytest: attachments upload/serve/scope/sniff, storage-location registration, embed promote 201/403/404, operator promote unchanged.
