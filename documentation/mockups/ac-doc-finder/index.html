2. Searching AutoCount

Shown when snapshots and the feed don't know the document, or while the current copy is still being fetched. The reads run in order (dates we already know, then modified-on going back 7 days, then DocDate going forward 14 days) and stop at the first hit. Stop is always available.

4. Design: the doc-type registry (not a screen)

Each AutoCount document type is one registry entry in code: its AutoCount paths, the number field and its date fields. The search code reads only the registry, so adding Invoice, Cash Sale, SO or RMA is one new entry (no other code changes) once its AutoCount path is confirmed on the host.

modules/autocount/doc_lookup/registry.py

Invoice		/invoicebydocdate?/invoicebyLastModified?DocNo · DocDate · LastModifiedIV, INV-path to confirm

Cash sale		??DocNo · DocDate · LastModifiedCS-path to confirm
sales_order
Sales order		??DocNo · DocDate · LastModifiedSO-path to confirm
rma
RMA		??DocNo · DocDate · LastModifiedRMA-path to confirm

Optional per entry: a direct by-number door, e.g. POST /api/DeliveryOrder/GetDeliveryOrder {"DocNo":[…]} (in the Postman collection, not yet verified on hapi.sorento.cc.cd). When it's enabled the search tries it first, which makes a lookup one read. It stays off until it's verified on the host.
