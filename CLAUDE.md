## What this is

FoundryX EMS — an Event Management System built as a **Platform-as-a-Service with an internal App Store**. The long-term goal is a revenue-generating product, so modularity, scalability, and maintainability are first-class constraints, not afterthoughts. Features ship as self-contained modules that can be zipped, certified, and installed/uninstalled across codebases.

The repo holds two independently-runnable apps plus the governing process docs:

- `service_frontend/` — Next.js 15 (App Router), React 19, Tailwind 4, Metronic v9.2.7 **demo1** layout.
- `service_backend/` — FastAPI + SQLAlchemy + Pydantic v2, owns auth and all domain data.
- `documentation/development_process/` — the binding governance + orchestration guides. Read these before non-trivial work.

## Architecture

### Multi-tenancy (SaaS — LIVE since sprint-1/07)
FoundryX EMS is a **multi-tenant SaaS**: many tenants on one deployment, one shared DB. The real tenancy model shipped in `documentation/plans/sprint-1/07-tenant-core.md`:
- **`tenant_id` on every tenant-scoped table** (core `public` tables and module tables alike). **Every repository query is tenant-scoped** — the tenant comes from the authenticated context (JWT claim), never from client input.
- **Tenant resolution = subdomain slug** (`acme.foundryxems.com`; dev `acme.localhost:3001` — browsers resolve `*.localhost`). Frontend `lib/tenant.ts deriveTenantSlug(host)` → NextAuth `authorize()` sends `tenantSlug` in the login POST; backend `AuthService.resolve_tenant` maps slug→tenant. Missing slug / bare host = `default`. Slugs: lowercase kebab 3–63, **immutable after creation**, reserved list mirrored frontend (`lib/tenant.ts`) + backend (`models/tenant.py RESERVED_TENANT_SLUGS`).
- **Tenant lifecycle** rides the core **`statuses` foundation** (`app/models/status.py` — `entity_type/key/category/label/color`, plan 07 §3): **code branches ONLY on the fixed `category`** (`ACTIVE/SUSPENDED/ARCHIVED`); label/color are display, editable later (BL-037; full engine BL-027). `Tenant.signin_allowed` is the single chokepoint — checked at login AND per-request in `_resolve_user` (suspend kills live sessions on their next request; archived = hidden in the console's Archived view, data intact; hard purge = BL-035).
- **Platform tenant** (`is_platform=true`, slug `platform`, seeded) hosts the operator team. `require_platform_permission(key)` = `require_permission(key)` AND `user.tenant.is_platform` (double lock). Platform permission keys live in `app/permissions/platform_permissions.csv` (module `platform`) and are **hidden from tenant callers** in `GET /permissions`; tenant Admin grant = core keys + INSTALLED-module keys (`seed.tenant_admin_grant(db, tenant_id)` — install-aware since plan 08). `User.tenant` + `Tenant.status` are `lazy="joined"` — the lifecycle/platform checks cost no extra query.
- **Provisioning** (`TenantService.provision`, POST `/platform/tenants`): tenant + seeded system roles (`seed_tenant_roles`) + first admin user (operator-set temp password — invite email BL-033) in ONE transaction. Self-signup (BL-032) must reuse this service.
- **Platform Console** = `/platform/tenants` (Resource shell clone; Active|Archived status views; suspend/reactivate/archive actions; "Open tenant" opens `<slug>.<domain>` via `lib/tenant.ts tenantUrl`). Menu section gated by `MenuItem.platformOnly` + `session.user.isPlatformTenant` + `can('tenants.read')`. Operator cross-tenant impersonation = BL-047.
- **Association `tenant_id` is derived, not defaulted** (BL-015 fix): `user_roles.tenant_id`/`role_permissions.tenant_id` resolve from the OWNING ROLE at insert (`models/permission.py tenant_id_from_role`) — never reintroduce a static default.
- **Isolation strategy is shared-DB + `tenant_id` row scoping** (not schema-per-tenant). Orthogonal to module schema-isolation: module schemas isolate *features*, `tenant_id` isolates *tenants' rows* within those tables. One deployment = one code version for ALL tenants — chargeable upgrades are **version-gated features** (`tenant_modules.installed_version`, plan 08), never per-tenant code.

### Auth flow (deliberately diverges from sorento_crm)
FastAPI owns auth end-to-end — it validates credentials and issues the JWT. NextAuth is only a session carrier: `CredentialsProvider.authorize()` (`app/api/auth/[...nextauth]/auth-options.ts`) POSTs to FastAPI `POST /auth/login`, stores the returned `access_token` in the NextAuth session, and `lib/api-client.ts` attaches it as `Authorization: Bearer <jwt>`. sorento_crm instead has NextAuth+Prisma own auth — foundryx does NOT. **Prisma is fully stripped** from the frontend; ignore Prisma references in the upstream Metronic README.

Login contract: `POST /auth/login {email,password,tenantSlug?}` → `{access_token, token_type, user:{id,tenantId,isPlatformTenant,email,name,avatar,roles:[{id,name}],permissions:[string],status}}`. Users are **multi-role** (M2M `user_roles`); the JWT carries `tenant_id` + `roles[]` claims (NOT permissions — see RBAC below); `get_current_user` resolves the user tenant-scoped via `UserRepository` and re-checks the tenant lifecycle per request. Unknown slug = uniform 401; suspended/archived tenant = 403 "This tenant is suspended." (`roleId`→`roles[]` sprint-1/02; `permissions[]` sprint-1/03; `tenantSlug`+`isPlatformTenant` sprint-1/07.) **Deploy note:** sessions issued before a new session field existed need one re-login (`permissions[]`, `isPlatformTenant`).

**Auth is platform core, NOT an App Store module** — it's the foundation every module plugs into (`Depends(get_current_user)`, core `public.users`). Don't package it as a module; modules depend on it.

### RBAC & permissions (sprint-1/03 — the gating contract every feature uses)
Every feature is **RBAC-controlled**. A permission is a flat key `"<resource>.<action>"` (e.g.
`users.create`, `orders.approve` — custom actions are first-class). Plan: `documentation/plans/sprint-1/03-roles-permissions.md`.
- **Catalog** is a global `permissions` table (no tenant scope) **synced from per-module CSV**:
  `<module>/backend/permissions/permissions.csv` (columns `resource,resource_label,action,action_label,description`).
  Core's CSV lives at `service_backend/app/permissions/permissions.csv`; `PermissionService.sync_permissions(module, rows)` upserts + deletes-by-module (App-Store install/update/uninstall), run for core at bootstrap/seed (core = "module zero"). **Add a permission = add a CSV row** (not code).
- **Grants** = `role_permissions` M2M (tenant-scoped via the role). **Implied-read:** any granted non-read action forces `<resource>.read`, normalized server-side in `RoleService` (blanket, incl. custom actions).
- **Enforcement (backend = the real boundary):** `require_permission("key")` dependency (`app/dependencies.py`) — per-request DB resolution via `effective_permission_keys(user)` (union over roles, read fresh — RBAC edits apply immediately; NOT from the JWT). **No superuser bypass** — but note since sprint-1/08 the tenant Admin grant is core + **installed-module** keys (`tenant_admin_grant(db, tenant_id)`; AppStoreService grants/revokes on install/uninstall), and platform keys additionally need platform-tenant membership (`require_platform_permission`). `GET /permissions` + `RoleService._grantable` hide/drop uninstalled modules' keys for tenant callers. Gate every protected endpoint; auth/`/auth/me`/health/`/me/preferences` stay perm-free.
- **Frontend gating (UX only):** `useCan()` (`hooks/use-can.ts`) reads `session.user.permissions`; `<RequirePermission permission>` wraps pages → friendly `NoPermission` page (never a raw 403); Resource shell honors `ResourceAction.permission` / `ResourceListConfig.createPermission` / `ResourceFormConfig.editPermission`.
- **Roles** carry `description` + `is_system` (seeded roles are system = delete-blocked, but name/desc/perms editable; toggle in Settings). Roles list/form clone the Resource shell; `GET /roles` is paginated, **`GET /roles/options`** is the lightweight (id,name) picker for the user form (authenticated-only). Endpoints: `/roles` CRUD + `/at` + `/export` + `/{id}/users` (assigned/assign/remove) + `/{id}/assignable`; `/permissions` (catalog).
- **Filter translator is entity-agnostic** (`services/filter_translator.py`): `translate_filter(group, columns, special?)` — each service passes its own whitelisted column map (+ optional resolver for M2M fields like users' `role`). Never hardcode one table.

### Impersonation (sprint-1/03 — test access as another user)
An authorized user (`users.impersonate`) browses with a target's **effective permissions**. `impersonation_sessions` table; the effective user is signaled per-request via the **`X-Impersonate-User-Id`** header (`lib/api-client.ts` attaches it from `lib/impersonation-store.ts`), honored by `get_current_user` **only** while an active session row matches (admin,target) AND the real user holds `users.impersonate`. **Security invariant: effective user = target (perms/view); actor = real admin (`get_actor_user_id`)** — writes are never attributed to the target. `get_real_user` (ignores the header) gates the `/impersonation/{start,stop,current}` endpoints so a session can't end its own. Rules: not self, target active + not an impersonator, **impersonator must hold ⊇ the target's permissions** (no escalation), same tenant. Collapsible amber banner in `app/(protected)/layout.tsx`; `useCan` reflects the target while active.

**Login = the reference implementation of the full DX + layering** (`app/(auth)/signin`, `components/auth/`, `hooks/use-signin`, `services/auth-service`; backend `api/v1/auth.py` → `services/auth_service.py` → `repositories/user_repository.py`). Current security posture: uniform `401 "Invalid email or password."` (no user enumeration), dummy-bcrypt on the not-found path (timing parity), server-side password policy, bcrypt 72-byte truncation in `security.py` (do NOT remove — bcrypt raises on >72 bytes). Remaining gaps tracked in `documentation/backlogs/backlog.md` (infra-vs-auth error messages BL-005, real captcha BL-041, per-tenant security policy BL-039).

### Auth hardening (LIVE since sprint-1/10 — forgot-password, rememberMe, throttle)
Plan: `documentation/plans/sprint-1/10-auth-hardening.md`.
- **Forgot-password** = `POST /auth/forgot-password {email,tenantSlug?}` — public, **always 200** with the uniform message (dummy token-gen on the miss path; outbox behavior must never leak existence). Issues a single-use token (invalidating the user's prior outstanding tokens), TTL `reset_token_ttl_minutes` (60m; invites `invite_token_ttl_minutes` 7d); email links → **`/change-password?token=`** (invites too). Redeem = existing `POST /auth/set-password` (single-use + expiry + full policy). Pages: `/reset-password` (request) + `/change-password` (redeem) on the login reference DX (`use-forgot-password`/`use-change-password` → `password-service` trio).
- **Password policy single source per layer:** backend `app/schemas/password.py validate_password_strength` (upper/lower/digit/special, 8–72) applied to `SetPasswordRequest`, `SignupRequest`, **`TenantProvisionRequest.adminPassword`**; frontend mirror = `app/(auth)/forms/password-schema.ts getPasswordSchema()` (tenant provision schema reuses it). Add a password-accepting schema → attach BOTH.
- **rememberMe (D4):** `LoginRequest.rememberMe` → JWT exp `remember_me_expire_minutes` (30d) vs `access_token_expire_minutes` (24h). NextAuth `maxAge` = 30d but the **backend JWT exp is the boundary** — `api-client` calls `signOut({callbackUrl:'/signin'})` on any **401-with-token** (backend 401 ⇔ token invalid/expired; permission problems are 403s — keep it that way).
- **Throttle (D5/D6):** `auth_throttle` table + `app/services/throttle.py` (`ThrottleStore` protocol; `DbThrottleStore` Postgres impl; Redis adapter = BL-040). Email scope: 5 fails/15m → 15m TEMP lock (success resets; never permanent — victim-DoS). IP scope: 20 fails/15m (login fails, every forgot-password request, failed set-password redeems). Checks run **before bcrypt**; over-limit = `429` + `Retry-After` (frontend `lib/throttle-message.ts` renders "~N minutes"; signin shows the backend detail — authorize() can't see headers). `trust_proxy_headers` (default false) gates X-Forwarded-For. Stale rows pruned by the dispatcher housekeeping pass. **E2E caveat:** locally EVERYTHING shares IP `127.0.0.1` — suite runs pump the shared bucket and 429 later manual testing/parallel specs; `DELETE FROM auth_throttle` when login flows 429 unexpectedly (local `.env` carries `THROTTLE_IP_MAX_FAILS=200` to soften this; one-command suite wiring = BL-061). The email-scope lock (5/account) is kept tight on purpose — that one you *want* to feel locally.
- **Signup parked (D3):** kill-switch `signup_enabled` (backend 404) + `NEXT_PUBLIC_SIGNUP_ENABLED` (`lib/auth-flags.ts` — signin link hidden, `/signup` + `/verify-email` render not-found). reCAPTCHA stub deleted (was never verified server-side); real captcha = BL-041, self-signup = BL-032.

### Frontend layering (enforced)
`UI component → custom hook → service → lib/api-client → FastAPI`. UI components receive data via props/hooks only and never call `fetch`/axios directly. Standards (evolved in sprint-1/02): **rich entities use the full-page Resource form** (`components/platform/resource-form`, read + global Edit toggle, record-nav, tabs) — modals reserved for trivial entities; **soft-trash + restore** (not hard-delete) for users. The reusable list/form shell lives in `components/platform/{resource-list,resource-form,resource-actions,multi-select,overflow-pills,status-badge}` and is config-driven (see `documentation/plans/sprint-1/02-user-management.md`).
- Key dirs (root-level, no `src/`): `app/` (routes — `(auth)`, `(protected)`), `components/ui/` (~78 shadcn/ReUI primitives), `components/auth/` (shared auth pieces — `AuthBrandPanel`, `AuthFooter`), `hooks/`, `services/`, `lib/`, `config/`, `providers/`.
- Path alias `@/` → repo root (see `components.json` aliases).

### Resource design language (the reuse contract — sprint-1/02)
Every list/form in the system is built on the **config-driven Resource shell** in `components/platform/` — do **not** hand-roll tables/forms. **Users is the reference implementation** (`app/(protected)/user-management/users/`); clone its shape for new entities.
- **New entity = a config + a few custom cells.** Write `useXListConfig()` → `ResourceListConfig` (columns, `viewKey`, `rowHref`, `fetcher`, `exporter`, `filterFields`, `exportColumns`, `actions`) and `useXForm()` → `ResourceFormConfig` (breadcrumb, tabs, `onSave`, `recordNav`). Wire `<ResourceList config>` / `<Form {...form}><ResourceForm config></Form>`.
- **List invariants:** full-width (`Container width="fluid"`), server-side sort/filter/search/paginate via `useResourceList`, per-user column prefs by `view_key` (`useViewPreferences` → backend), fixed columns set `meta.reorderable=false` (stay pinned), multi-value cells use `OverflowPills` (width-aware `+N`), pick-many fields/filters use `MultiSelect` (search + select-all + pills), status via `StatusBadge` + a per-entity registry, one **action registry** surfaced in row `…` / bulk dropdown / form `…`. The Active|Trashed segmented control relabels per entity via `statusViewLabels` (tenants use Active|Archived); selected segment = filled primary; **row selection clears on view switch** (selection belongs to its view — don't undo this, it fixed silent cross-view exports).
- **Card view (sprint-3):** a config `cardRender` (returns the card BODY) + `defaultView` light up a **card/list view toggle** (Grid/List icons), persisted per user per `viewKey` in localStorage. The shell wraps each card with the selection checkbox + the row `…` action menu; the card grid reuses the SAME data/search/filter/segment/pagination/bulk as the table (Columns + column-DnD are list-only). A config `rowHref` of `'#'`/`''` opts a list out of row/card navigation (no detail page). First adopter = the App Store (card default).
- **Form invariants:** read by default + **global Edit toggle** (single PATCH, dirty-guard), icon tabs, circular `N / M` record-nav carried in the URL (`?ctx=&i=`), required fields marked with `*` via `FormRow`.
- **Backend per entity:** Pydantic schemas expose **camelCase** (`Field(validation_alias="snake_case")` + `from_attributes`); recursive filter goes through a **whitelisted** translator (never arbitrary columns); every repository query is tenant-scoped.

### Design system (FoundryX brand)
- **Tokens:** `css/foundryx-tokens.css` — imported AFTER `config.reui.css` so FoundryX values win over Metronic defaults. Primary brand = **orange `#FF5A00`** (`--primary`). Source of truth = `documentation/ui_ux/FoundryX-{Light,Dark}.TokensStudio.json` (Figma Tokens Studio export).
- **Fonts:** Poppins (display — `font-heading` utility) + Inter (body, default `font-sans`), both via `next/font/google` in `app/layout.tsx`.
- **Figma → code:** designs pulled via the Figma REST API (`/v1/files/<key>/nodes`, `/v1/images` for PNG/SVG export). The Metronic file key is `fPQB8IuZ76vLaHOjMQqsfA`; brand assets land in `public/media/foundryx/`. Build UI from the Figma frame, not guesswork.
- Governance reminder: Metronic utility classes only — **no `<style>` tags, no raw CSS** (the old `branded.tsx` `<style>` block was removed for this reason).
- **Responsive — mobile AND desktop (user mandate):** every screen must look good and be usable at **both desktop and mobile** widths (no horizontal scroll, no clipped/overlapping controls, drawers/dialogs/tables/canvas all reflow). Build mobile-first with Tailwind responsive prefixes (`sm:`/`md:`/`lg:`); side-by-side panels (palette · canvas · drawer; list ⇄ detail two-panes) must stack or collapse on small screens. **Verification is required, not optional:** check each new/changed surface at a desktop viewport (~1280px+) AND a mobile viewport (~375px) — in Playwright use `page.setViewportSize(...)` / a mobile project, or screenshot both. A feature isn't done until it's confirmed at both sizes. (The workflow canvas now stacks its palette·canvas·drawer columns on mobile + scrolls each panel to the canvas height — done in slice 09.)
- **Foolproof-UI / no-inline-instructions rule (user mandate):** the UI must be self-evident from its controls, labels, and layout alone — **never add instructional/teaching/hint copy on the screen** ("Click or drag a node onto the canvas", "Connect a node's bottom handle…", field captions explaining mechanics like "available as trigger.input.*"). It clutters the surface and a well-designed UI shouldn't need to teach. Allowed: concise field **labels**, a node/entity's one-line **description** (identifies *what* it is, not *how to use* it), and short empty-state status ("Select a node to inspect"). NOT allowed: procedural how-to text. Proper onboarding = a real **guided product tour** (BL-085), not sprinkled hints.
  - **Only offer valid options; warn on missing prerequisites (user mandate, learned plan-09):** a picker must surface only choices that will actually work — the `entity.update` field picker lists ONLY server-writable fields (not every record field), the status-change entity picker lists ONLY status-engine entities. A node that needs a resource the workspace lacks shows a **warning** (e.g. email/storage action with no connection configured), never a silent later failure. Foolproof = the UI can't be configured into a guaranteed runtime error.
  - **Don't auto-derive ambiguous actions (user mandate, learned plan-09):** auto-connecting a new canvas node "from the nearest leaf" felt helpful but forced WRONG edges (an action meant for an IF false-branch wired to the true-branch node). When the right target is ambiguous, do nothing and let the user choose. Convenience that guesses wrong is worse than an explicit step.
- **Canvas-editor interaction principles (workflow/status editors, learned plan-08/09):** these are the baseline interactions any node-graph editor must have, and the lessons that hardened them:
  - **Long catalogs collapse + search, never flat-list:** the node palette is collapsed-by-default sections with counts + a search box (a flat list grows unusable as the catalog grows). Same for in-canvas menus — a "Replace node" list became a compact two-view menu (Replace ▸ → searchable scrollable submenu), not an inline list.
  - **Every dropdown is a searchable `SearchSelect`** (reinforces the BL-062 mandate) — `select`/`template` fields, entity/status/field pickers, even 2-option toggles. Multi-value pickers get `MultiSelect` (search + select-all). No bare shadcn `<Select>`.
  - **Side panels match the canvas height + scroll internally** (`lg:h-[calc(100vh-…)] overflow-y-auto`) — they must NOT stretch the page; long palettes/drawers scroll within their own bound. On mobile the palette·canvas·drawer columns stack (`flex-col lg:flex-row`).
  - **Floating menus clamp into the viewport** — a cursor-anchored context menu near an edge measures itself (`useLayoutEffect` on the ref) and flips up/left to fit; never let a popup truncate off-screen.
  - **Standard node interactions:** right-click → context menu (replace / delete), keyboard **Delete/Backspace** removes the selected node — but the delete guard must skip when focus is on ANY interactive control (`button, [role="combobox"], …`, not just `input/textarea`), since SearchSelect/dropdown triggers are buttons and a reflexive Backspace would otherwise destroy a node mid-config.

  - **Quick-replace in place:** swap a node's catalog type (same kind) keeping its id/position/name/edges (resets config to the new type's defaults) — from both the drawer's type SearchSelect and the context menu.

### Storage provider migration + centralized background jobs (LIVE since sprint-4/10 — closes BL-077)

So migration: create connection **B**, flip the storage write-target to B, mark **A `is_active=false`** — all in ONE txn at START. New uploads land on B immediately; A is frozen + only DRAINED (its snapshot copied). Reads serve from A (old keys) and B (new keys) throughout — zero downtime. Cutover = **batch value-checked rewrite** `conn:A:`→`conn:B:` (`WHERE col LIKE 'conn:A:%'` — a row re-pointed mid-run is already `conn:B:` so never clobbered). A lingers inactive (audit + serves failed stragglers); its bucket contents are NEVER touched by us.
- **`is_active` on `connections` unifies retire + transient coexistence + write-target.** "Active storage connection" = the single `is_active=true` storage row → `resolve_for_type` filters `is_active`; resolve-by-KEY (`get_by_id`) ignores it (retired A still serves). Unique index relaxed to `WHERE type != 'payment' AND is_active`. The write-target flip IS the `is_active` flip (no extra pointer column).
- **Copy must PRESERVE the raw path** — `save()` mints a fresh uuid → WRONG for copy. New adapter `put_raw(raw, content, mime)` writes at the EXACT key; then rewrite is a trivial prefix swap and resume needs no `{rawA→rawB}` map. **Continue-on-bad-blob** (missing source = record `failed`, skip, never abort; failed keys NOT rewritten, A NOT retired for them). **Partial cutover**: rewrite only successfully-copied keys; failures=0 → auto-cutover, ≥1 failure → HOLD at `needs_review` (explicit Complete/Retry). Orphans in B (mid-run replace/delete) ignored v1 (never served) — GC = BL-126.
- **`StorageKeyLocation` registry = the generic "find every stored key" seam** (mirrors StatusEntity/FactSource/ImporterDef). Scalar `*_key` columns register declaratively (`users.avatar_key`, `tenant_branding.*_key`, `import_jobs.*_key`, `documents.storage_key`, omnichannel `conversation_messages.media_key`, …); JSON-embedded keys (form `answers_json`, template block-docs) register a `rewrite_json` callback that **reassigns a fresh dict** (the SQLAlchemy in-place-JSON-mutation gotcha). Modules register their own locations at install. A **drift test hard-fails CI** if a `*_key` column is unregistered — the thing that actually saves future-you (loud at build, not silent at migration). Enumeration is **connection-scoped, not tenant-scoped**: a tenant-own connection's keys live only in that tenant's rows; the PLATFORM connection's keys span every fallback tenant → same code path sweeps both (tenant-own vs platform cross-tenant derived from `connection.tenant_id == PLATFORM_TENANT_ID`). Dedicated perm `integrations.migrate_storage` (+ grant sweep for existing tenants).
- **Centralized `background_jobs` table** (new core `public`) = generic `type`-dispatched job + worker + ONE "Jobs" activity drawer; storage migration is its FIRST `type`. Columns: `type/status/payload_json/result_json/cursor_json/progress_{total,done,failed}`; `register_job_handler(type, handler)`; eager-inline in dev, Celery in prod; atomic status-claim (import-engine double-commit guard); `cursor_json` = resume point; retention pruner in the beat task. Existing job tables (`import_jobs`/`document_download_jobs`/`workflow_runs`/`email_outbox`) LEFT UNTOUCHED (load-bearing/typed) — retrofit = BL-125. **When adding ANY new async worker-processed job, use `background_jobs` + a registered handler, not a new bespoke table.**
- **Build lessons (learned the hard way this slice — apply to any engine like it):**
  - **A data-backfill migration must NOT commit Alembic's own connection.** `Session(bind=op.get_bind())` + a per-batch `db.commit()` fires a real `COMMIT` on Alembic's migration connection mid-run and corrupts the `alembic_version` stamp on live Postgres (invisible to pytest — conftest is `create_all`, module Alembic is a Postgres-only no-op). Run a batched backfill on a **separate** `create_engine(settings.database_url)` connection (dispose it in `finally`); the revision must alter no schema so the side connection reads already-committed data. Every OTHER migration in the repo uses `op.get_bind().execute(...)` and lets Alembic's transaction commit at the end — match that.
  - **A long worker job that supports abort needs COOPERATIVE cancellation.** Eager-mode (dev/test) runs the handler inline with no interleave, so an abort-doesn't-stop-the-worker bug is INVISIBLE to the suite. The copy/work loop must re-read its own `status` fresh from the DB at each checkpoint (a concurrent abort committed `JOB_ABORTED` on another session) and bail BEFORE the terminal step — else the worker finishes and overwrites the abort. `db.query(BackgroundJob.status).filter(id==).scalar()` after each commit.
  - **`create_all` NEVER ALTERs an existing table.** Adding a column to an existing core table (`connections.is_active`) is invisible after `init_db` (which is `create_all`+seed) → the app 500s on the missing column. Reset/deploy a feature that adds a column with **`bootstrap_db`** (runs `alembic upgrade`), never `init_db`. The pre-existing `integrations.spec.ts` failing identically was the tell it was env, not code.
  - **A NEW module table does NOT auto-appear on a legacy `create_all` local DB — neither boot path materializes it.** `run_module_migrations` only `upgrade head`s when a `<schema>.alembic_version` row EXISTS; a legacy create_all DB has **no such row**, so it takes the *"no row + tables exist → stamp head, NO DDL"* adopt path (and if module Alembic never initialized at all — no `alembic_version` table — nothing runs). `install()`'s `create_all` runs on **first install only**, not every boot. Net for local testing: adding `idea_attachments` in migration 0007 + rebooting left the table absent → the Ideas read 500'd `relation "app_ideation.idea_attachments" does not exist`, surfacing as "Failed to fetch" in the FE. **Local fix before testing a new module table: run `IdeationBase.metadata.create_all(engine)` (or apply the migration DDL directly) — do NOT assume `next build`/uvicorn boot creates it on a pre-existing DB.** Prod is fine (deploy runs `bootstrap_db`/module upgrade on a version-stamped DB). Same family as the `create_all`-never-ALTERs bullet above and the `embed_connections` local-gap.
  - **A drift-test exclude-set is a decision-forcing seam, not a dumping ground.** `media_sample_key` (a REAL storage key) was parked in the exclude-set and would have silently never migrated; the drift test exists precisely to force "register it or justify the exclusion." Audit the exclude-set — a genuine key hiding there is a stranded-asset bug in waiting.
  - **Unit-test the backfill FUNCTION directly**, not just the migration wrapper — module Alembic doesn't run under conftest, so the function is the only thing pytest actually exercises; verify the migration wrapper separately on live Postgres.

### Sprint-3 F4-foundations process lessons (08→11, learned the hard way)
- **Stale `next-server` port ownership is the #1 time sink.** A sibling worktree's `next start` (or a prior one) holding :3001 serves OLD chunks → the page 400s on chunk hashes / renders an old build / "ChunkLoadError". ALWAYS `pkill -9 -f next-server` + confirm `:3001` free before a clean `npm start`; check `lsof -p $(lsof -ti :3001) | grep cwd` + the next-server version. After ANY frontend change: `rm -rf .next && npm run build` then a single clean start. `next.config` has `output: standalone` so `next start` warns (harmless, still serves).
- **`uvicorn` WITHOUT `--reload` won't pick up new ROUTES/code after edits** — restart it. DB/migration/perm changes ARE seen live (queried fresh). After adding a migration, run `alembic upgrade head` on the LIVE Postgres before live-testing.
- **A browser "CORS / No Access-Control-Allow-Origin" on ONE endpoint while siblings work = a server 500 on that route** (a 500 thrown before CORS headers attach), NOT a CORS config problem — check the uvicorn log (bit us when a table/route was missing).
- **Alembic revision-id collision**: some migration files use `revision: str = "..."` so a bare `^revision = ` grep misses them — check ALL existing ids (a chosen id already belonged to `tenant_branding`). Collision → "present more than once" + a false "cycle detected".
- **A new core permission doesn't reach existing tenants' Admin roles automatically** — `tenant_admin_grant` is computed at provision/seed. A tenant provisioned before the perm shows "no access" until re-granted (`admin.permissions = tenant_admin_grant(db, tenant_id)`). Worth a migration sweep when adding a core perm.
- **Lint gates the prod build**: no statement-position ternaries (`a ? b() : c()` → `if/else`), no unused imports; **spreading a `Set` needs `Array.from`** (downlevelIteration). `npx eslint <files>` before `npm run build`.
- **Foolproof-UI (reinforced):** a workflow node's bold label is its **editable name**, the type is separate — a node named "Record created" was actually `entity.field_changed`. The card now shows the real type in the subtitle when a custom name diverges, so a name can't masquerade. Apply this "state what it IS" rule to any node/card with an editable name.
- **E2E live-verification via Playwright MCP**: drive a real session (set inputs via the value-setter + `requestSubmit`), navigate, assert DOM — invaluable for catching the stale-build + perm-grant issues that unit tests miss.

## Module / App Store governance (`documentation/development_process/EMS_Developer_Governance_Framework.md`)

Every feature is packaged as a self-contained module that the App Store installer certifies. Violations are rejected by the installer.

- **Manifest:** each module has a root `manifest.json` (`module_name`, `version`, `author`, `required_core_version`, entry-point routers).
- **Folder structure:** `/<module>/frontend`, `/<module>/backend/{routers,services,repositories}`, `/<module>/backend/permissions/permissions.csv` (declares the module's RBAC permissions — see RBAC above), `/<module>/alembic`, `manifest.json`.
- **No global pollution:** modules cannot inject into core `main.py` or global stores; hook in via predefined Event Listeners. Frontend modules wrap in an Error Boundary so a crash doesn't take down the EMS dashboard.
- **DB = Schema-Isolated Relational Architecture:** modules create real Postgres tables but inside their own schema (e.g. `CREATE SCHEMA app_commercial;`), never in `public`. Cross-schema linkage via FK into core tables (e.g. `app_commercial.invoices → public.projects(id)`). Never `DROP`/`ALTER`/`TRUNCATE` core `public` tables.
- **Module-isolated migrations (Alembic):** each module tracks its own history in a per-module version table (e.g. `alembic_version_commercial`) so uninstall = drop the module schema + its version table, leaving core clean.
- **No global CSS:** use Metronic utility classes only — no `<style>` tags, no global `.css` overrides.

#### Public consumer gateway — respond.io response parity (MERGED to main, `sprint-4/omnichannel-respondio-parity`)
The public gateway (`/api/v1/omnichannel/*`, workspace-API-key auth via `get_api_workspace`, NOT session JWT) mirrors respond.io's **response shapes** so external consumers can use it like respond.io. - **⚠️ THE CONSUMER GUIDE IS PART OF THE CONTRACT — change the wire, change the guide, same commit.** `documentation/api/omnichannel/foundryx-omnichannel-consumer-integration-guide.md` (also published at `doc.foundryx.my`) is what external integrators build against. Reconciled 2026-08-09. Rules now: (a) the guide lives IN the repo so a wire change and its doc diff land in one reviewable commit — if you touch `Rio*` schemas or `api_v1.py`, the reviewer must see the guide diff too; (b) never justify a breaking gateway change with "only external clients consume it"; (c) `tests/test_omnichannel_api_gateway.py` carries **contract-drift regressions** (timestamp / cswExpiresAt / payload / caption-split) — they exist to fail loudly, don't relax them.
- **Gateway read shapes must stay LOSSLESS vs the internal `MessageItem`/`ThreadItem`.** The 07-11 reshape dropped `createdAt` (⇒ inbound messages had NO time at all, since `status[]` is receipt-driven and inbound never gets one), `cswExpiresAt` (⇒ the 24h free-form window was undetectable — consumers had to force template-only sends or provoke a `409`), plus `payload` (interactive buttons / location coords flattened to a lossy text summary), `mediaSize`, `reactions`, `replyTo`. All restored 2026-08-09: `RioMessageItem.timestamp` (epoch, **inbound AND outbound**), `RioContactItem.cswExpiresAt` (ISO-Z — FX extension, so house convention, not respond.io epoch), `message.payload`/`message.size`, `reactions[]`, `replyTo`. Renaming for parity is fine; **dropping a field the internal shape carries is not** — a consumer has no other source for it.
- **Two shapes coexist by route, deliberately**: `/api/v1` READS = `Rio*`; **webhooks + the comment-create response = `MessageItem`/`ThreadItem`** (`inbound_service` builds webhook payloads from `conversation_service.message_items()`). Webhooks were never reshaped and are the richer surface (`senderName`, `priority`, `unreadCount`, `lastMessagePreview`). Guide §9.1/§9.2 documents both, §9.3 maps them. Don't "unify" one into the other without a consumer migration.
- **A media message's body is its caption, exposed ONCE** — `message.caption`, with `message.text` null (populating both read as a duplicated body). An internal note (`sender.source == "system"`) still reports `traffic: "outgoing"` — `sender.source` is the discriminator; documented rather than re-enumerated, since `traffic` is respond.io's two-value field.
- **respond.io parity schemas are plain `pydantic.BaseModel`, NOT `ApiModel`** (`schemas.py` `Rio*` classes) — deliberate: `ApiModel`'s camelCase-alias + `Z`-datetime serializer would fight respond.io's exact field names. Parity needs snake_case where they use it (`custom_fields`, `created_at`), **epoch-second int timestamps** (`_epoch(dt)` off the aware-UTC `UTCDateTime` columns), and a `{items, pagination:{next,previous}}` envelope. When a wire contract must match an EXTERNAL spec's exact field names/types, bypass `ApiModel` with a dedicated BaseModel family (don't fight the house serializer).
- **Our ids are UUID strings; respond.io's are int64** — `id`/`messageId` stay strings (documented, unavoidable deviation — can't fabricate stable ints). Fields we don't model (contact `language`/`countryCode`/`tags`/`lifecycle`/`isBlocked`, and `priority` — respond.io has no contact-priority field) emit `null`/`[]`/`false`; the value still writes server-side (PATCH), it's just not echoed in the parity shape.
- **Signed, clickable media URLs (the security-sensitive bit).** Public message `message.url` is now an ABSOLUTE, HMAC-signed, time-limited link (`{public_base_url}/omnichannel/media/{id}?exp=&sig=`, `security.py signed_media_url`/`verify_media_sig`/`_media_sig` — HMAC-SHA256 over `f"{id}:{exp}"` keyed by `settings.jwt_secret`, TTL `media_signed_url_ttl_seconds` default 3600). The media route (`routers/media.py`) accepts `exp`+`sig` → verifies → serves with **NO Authorization header** (the signature IS the authz; opens on a raw browser click, the whole point). Rules that made it safe: **the signature binds the exact message id** so it can't be re-pointed; **`hmac.compare_digest`** constant-time; **expiry checked before compare**; the unscoped `ContactRepository.get_message_global` is reachable **ONLY after** a passing verify (never from a normal request path — that stays tenant-scoped `get_message`). The internal inbox `media_url_wire` (relative, Bearer via `apiFetchBlob`) is UNCHANGED — the public mapper builds its own signed URL, it does not repurpose the model property. Capability-URL semantics (bearer-less, replayable within the TTL) are inherent to signed URLs and are the intended design.
- **Two-way keyset message cursor.** `list_messages_recent` gained `after_id` (newer-direction) alongside `before_id` (older); both keyset on `(created_at, id)` and always return oldest→newest. Router builds `pagination.next` (=older, `before=oldest`) + `pagination.previous` (=newer, `after=newest`) as ABSOLUTE URLs via `request.url.replace_query_params(...)` (replaces the whole query — pass EVERY param you want retained; it preserves the path + `{identifier}`). Known v1 imperfection (accepted): after a partial forward page `next` is `None` even though older history exists (gated on `len==limit`).
- **Template filters**: `GET /templates` gained `channelId` (default = the workspace's active channel; unknown = 404 `channel_not_found`), `search` (name `ilike`), `category` (Meta category, upper-cased).
- **Tenant-scope stored user ids at USE time (review catch, the polymorphic-target_id rule again):** the assignee display lookup (`_users_by_id`) resolves `contact.assigned_user_id` — filter `User.tenant_id == tenant_id`, never a bare `User.id.in_(ids)`, even though `patch_thread` validates on write. Any mapper that resolves a stored user/role/record id needs the tenant filter as defense-in-depth.
- Tests: `tests/test_omnichannel_api_gateway.py` (existing gateway tests updated to the new shapes + 4 new — signed-media serve+tamper+expiry, two-way cursor, template channel/search/category). Deploy note: a host still 404ing `/api/v1/omnichannel/*` is running a build that predates the gateway slice OR has omnichannel inactive — a code/deploy gap, not a bug.

## Development methodology (mandatory order)

This is a strict, governed process — follow it for every feature. Source: the user's `/init` directive + `documentation/development_process/`.

1. **Design first in Figma.** Define design-system variables and components in Figma before coding. Build UI strictly from Figma components.
2. **Component-library discipline.** Reuse components wherever possible. If a new component or variant is needed, build it in the shared component library first, then consume it on the target page — never one-off inline.
3. **Grill → UAC → plan.** Every piece of work starts with a **`grill-me`** session: the user wants to be grilled on the design — frontend AND backend — before any code is written. The grilling resolves the full decision tree.
   - **UAC FIRST, then the plan (MANDATORY).** Once the grill settles the design, **write the User Acceptance Criteria file BEFORE the plan**: `documentation/plans/sprint-<N>/<NN>-<feature>-acceptance-criteria.md`. It is the independently-verifiable Given/When/Then list (per-AC id, grouped by slice, tagged `[BE]`/`[FE]`/`[E2E]`/`[T]`) the feature must satisfy — the **contract**. **THEN** write the plan (`<NN>-<feature>.md`) as the design that *fulfils* the UAC. The Playwright Test Execution Report (step 7) is keyed back to the UAC ids (PASS/FAIL/DEFERRED per id). **No plan ships without its UAC file**; a slice is "done" only when its UAC ids pass. Reference format: any existing `*-acceptance-criteria.md` (e.g. `sprint-4/03-...-acceptance-criteria.md`).
   - **Plans live in `documentation/plans/sprint-<N>/`**, numbered + clearly named (e.g. `01-login-page.md`). One plan + one UAC file per feature.
   - **Backlogs live in `documentation/backlogs/backlog.md`** — a single register table (`ID · Title · Source plan link · Priority · Status`). When a plan defers something (hardening, follow-ups, migrations), log it here with a link back to the source plan so it isn't forgotten.
4. **Frontend-first.** UI/UX is the top priority. Build and fine-tune the frontend **before** the backend, using a **mock service behind the service layer** (UI → hook → service → mock) so all states (loading/error/success) are tunable with no backend running. Iterate until the UI/UX is satisfactory.
5. **Backend second.** Only once the frontend is satisfactory, wire the real backend: implement/refactor endpoints (Service-Repository), then swap the mock service for the real `api-client` call. Behaviour swap should be a one-line change at the service boundary.
6. **TDD.** Red-green-refactor, both layers. Frontend component/validation tests (Vitest + React Testing Library) in the frontend phase; backend tests (pytest + httpx) in the backend phase. Tests precede implementation.
7. **Playwright E2E verification.** `@playwright/test` specs must **simulate real user clicks** (navigate by clicking through the UI) — never shortcut by navigating directly to a page URL, because real users don't know URLs. Run against the mock in the frontend phase, then re-run against the live backend. The QA step produces a Markdown Test Execution Report (User Story / Scenario / Precondition / Steps / Expected / Actual / Remarks) per `AI_Agent_Orchestration_Guide.md` §6.
   - **Spec isolation:** the suite runs `fullyParallel` — a spec that MUTATES shared tenant state (e.g. uninstalling a module on the `default` tenant) breaks concurrent specs mid-run. Such specs must provision a **dedicated tenant** first (operator-API setup is fine; the flow under test stays real clicks). Learned in plan 08: the app-store lifecycle spec on the default tenant intermittently broke a parallel omnichannel spec.
   - **Known env failure:** with real `NEXT_PUBLIC_META_APP_ID`/`NEXT_PUBLIC_META_ES_CONFIG_ID` set in `.env.local`, `omnichannel.spec.ts › connects a channel via Embedded Signup` fails by design (the wizard launches the real Meta SDK; the spec drives the simulated popup). Not a regression — passes with the Meta env unset.
   - **E2E residue accumulates** (learned plan 09): provisioned `e2e-*` tenants are never purged (BL-035) and eventually crowd seeded rows off the tenants list's page 1, breaking `tenants.spec.ts`; a fixed-name entity left by an interrupted run (e.g. `E2E Temp Role`) breaks its spec's next run on the unique-name check. Rules: timestamp every E2E-created name (never a fixed literal), and when the suite fails oddly, suspect residue before code — clean `e2e-%` tenants + leftover `E2E *` rows from the local DB.
   - **Wrong-build gotcha (learned plan 05):** with concurrent worktrees (`.claude/worktrees/*`), whichever process grabbed port 3001 first serves it — an `npm start` from THIS dir silently no-ops if a sibling worktree's server already holds the port, so E2E runs the WRONG branch's build and fails inexplicably (e.g. a menu item missing). Confirm ownership: `lsof -p $(lsof -ti :3001 | head -1) | grep cwd`. After any menu/route/config change, do a CLEAN rebuild (`rm -rf .next && npm run build`) before `npm start` + E2E — a stale `.next` renders the old menu.
   - **Mailbox-asserting E2E rig (learned plan 10):** specs that must READ delivered mail (reset links) need the maildir-handler smtpd, not the plain debug one: `python -m aiosmtpd -n -l localhost:1025 -c aiosmtpd.handlers.Mailbox /tmp/foundryx-e2e-mailbox` — pre-create `tmp/new/cur` subdirs (the handler doesn't) or every send 500s with FileNotFoundError, and check WHO owns :1025 first (a leftover plain `aiosmtpd` from an earlier session binds the port, swallows mail, stores nothing — the same port-owner discipline as 3001/8001). Wiring this into Playwright global-setup = BL-061. Quoted-printable bodies: strip soft breaks (`=\r?\n`) + decode `=3D` before regexing tokens out of the mail.
8. **Code review.** A code-review agent must approve before merge to `main`.
9. **Branching.** Each piece of development starts on a new branch named `sprint-<N>/<feature>` (e.g. `sprint-1/login-page`); merge to `main` only after review passes. (`git init` before starting branch-based work if the repo isn't yet versioned.)
   - **Concurrent plans:** park a branch with a `wip(...)` commit before switching to another plan's branch; finish/review/merge the parked branch from a **git worktree** (`.claude/worktrees/<name>`, symlink the backend `.env` + frontend `node_modules` in — both are gitignored) so the main checkout stays on the active plan.
   - **Servers track the checked-out code:** uvicorn `--reload` and the served Next build run whatever branch their directory has checked out. After any branch switch (or when working split across a worktree), restart/rebuild the side that moved — a frontend built from branch A against a backend on branch B fails with confusing 404s ("Not Found" alert on new pages was exactly this in plan 08). When a page 404s or perms vanish unexpectedly, check WHICH tree owns the port: `lsof -p $(lsof -ti :3001) | grep cwd`.
   - **One Postgres serves every worktree/branch** (learned plan 09): `init_db`/`bootstrap_db` run from a branch whose permission CSVs lack another branch's rows will DELETE those rows (`sync_permissions` is delete-by-module) — mid-session this silently 403s the other branch's features. Don't reseed from a stale branch while another branch's feature is under test; reseed from the branch you're serving.
   - **The user codes concurrently in the main checkout** (learned plan 10/sprint-2-01): uncommitted user edits appear mid-session and twice blocked a checkout/rebase. ALWAYS `git status` immediately before any branch operation (merge/rebase/checkout) — never assume the tree you saw earlier is still clean. In-flight user wip: ask before touching; `stash → rebase/merge → stash pop` with explicit consent is the proven recovery. Also: a parked branch's wip commit may be AMENDED or superseded by the user between your turns — re-read `git log` before building on it.

### Code-review hard-fail rules
The reviewer rejects: DB queries / raw SQL inside a router; a React component calling axios/fetch instead of going through a custom hook; `any` types (every component exports explicit TS interfaces); raw CSS / injected `<style>` tags; a module altering core DB tables.
Also reject (learned sprint-4/05): a "done" slice still serving a frontend mock with no real backend swap; a new entity column/engine adoption with no backfill for rows/tenants that already exist; code that hardcode-looks-up a tenant-editable key; a new permission with no grant path for existing tenants.

## Definition of Done + recurring-gap gate (learned the hard way — sprint-4/05 Cluster D)

As the codebase grows the early design principles (frontend-first, reuse, foolproof-UI) get lost and slices ship "done" while real user-facing gaps remain. A slice is NOT done until this gate passes — the reviewer checks it, and every subagent brief must carry it:

1. **Mock swapped to real.** A frontend-first phase-1 mock (an in-memory `*-service` like `event-billing-service.ts`) is DEBT, not done. The slice is incomplete until the real backend is wired AND verified showing real data. Tag every mock loudly (`PHASE 1 MOCK`) + log a backlog item; never let a mock reach a "verify from the user's perspective" QA pass. (Cost us a whole cluster of fake Aisha/Marcus ticket rows.)
2. **New column/engine on an EXISTING entity needs a BACKFILL migration**, not just seed-if-absent. Adding the status engine to `tickets` left old rows `status_id=NULL` (transition-from-None 500) and existing tenant graphs un-seeded. `update_tenant` seed-if-absent does NOT repair rows/graphs that already exist — ship a backfill (legacy enum → status_id; repair existing tenant graphs).
3. **Tenant-editable KEYS are a code contract.** Code that looks a status up by key (`"issued"`, `"transferred"`) breaks the instant a tenant renames it. Either lock keys from tenant editing (system rows) or never hardcode-lookup an editable key. (A tenant forked the ticket graph to Draft/Confirmed → every scan/transfer 409'd.)
4. **A new core/module permission does NOT reach existing tenants' Admin** — the grant is computed at provision/seed. Adding a perm needs a grant sweep (migration or `tenant_admin_grant` re-run) for existing tenants, else the feature silently 403s / the action is invisible. (Recurring — the Nominate action was hidden until re-granted.)
5. **Verify end-to-end with REAL data from the user's perspective**, at 375px AND 1280px, on a freshly REBUILT frontend (`rm -rf .next && npm run build`) against correctly-owned ports (3001 frontend, 8001 = FoundryX — kill any sorento squatting 8001). Tests passing ≠ user-verifiable: conftest uses `create_all`, so a broken Alembic migration (e.g. a revision id > 32 chars vs `alembic_version.version_num VARCHAR(32)`) passes the suite yet breaks every real deploy.

### Agents-team orchestration (what works — sprint-4/05)
Building a slice with a subagent team (coder → tester → reviewer, looped on findings) held quality far better than solo as the codebase grew. Make it repeatable:
- **Every coder/tester brief MUST embed the Definition-of-Done gate above + the hard-fail rules** — a subagent starts with zero project memory, so the brief is its only guardrail. Don't assume it knows frontend-first/reuse/foolproof-UI; state them.
- **Audit before building.** An Explore agent producing a per-AC gap matrix (backend exists? frontend exists/mock/missing?) before any coder runs prevents building blind and surfaces the mock/backfill/perm gaps early.
- **Sequential coders on a shared branch** (not parallel same-tree) when tasks touch overlapping files — parallel edits to one working tree race. Use worktree isolation only when tasks are file-disjoint AND each worktree has its own node_modules/.venv.
- **Tester verifies from the USER's perspective** (real clicks, real data, fresh build) and writes an AC-id-keyed PASS/FAIL/DEFERRED report — not just green pytest. The reviewer re-checks the recurring-gap gate, not only correctness.
