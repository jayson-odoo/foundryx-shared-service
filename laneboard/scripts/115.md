# Hand test - PR #115 SS-DEBTOR-AGENT (Debtor SalesAgent -> `sales_agent_code` on the customer feed)

## URL
crew test copy

## Setup
- Data migration only, no schema change. The test copy's boot / `python -m scripts.bootstrap_db` runs module migrations up to `0029_autocount_sales_agent`, which adds the `SalesAgent -> sales_agent_code` row to every EXISTING customer task that already has mapping rows.
- Sign in as a tenant Admin (holds `autocount.companies.manage`).
- Company A: an AutoCount company whose Customer entity uses the open REST API (connection base URL `https://hapi.sorento.cc.cd/api/db1`, read only, no IP limit, path `/debtorbypage`) and that already had a customer mapping before this deploy.
- Company B: an AutoCount company on the same kind of open REST API connection with NO Customer entity yet.
- Do not push customers to a real Sorento until the sorento CUSTOMER-SALES-AGENT lane is deployed (see the last Expected line). Never paste fetched debtor rows into a ticket, doc or commit (sorento-crm is public).

## Steps
1. Sidebar: AutoCount > Companies, click Company A, click the "Entities" tab.
2. On the Customer row, open "..." and click "Configure mapping".
3. Find the row whose AutoCount field is `SalesAgent`.
4. Click "Simulate mapping". Replace the "AutoCount record (in)" box with exactly: `{"AccNo": "300-Z001", "CompanyName": "Sim Debtor", "Phone1": "", "IsActive": "T", "SalesAgent": "  AGENT X III ", "Data": [{"AutoKey": 1, "LastModified": "2026/09/01 10:00:00"}]}`
5. Click "Run simulation" and read "Sorento record (out)".
6. In the same box change `"  AGENT X III "` to `""`, click "Run simulation" again.
7. Close the dialog. Click Back, open the Customer row "..." > "Configure source", click "Test".
8. Scroll the preview table right to the `SalesAgent` column and compare a few rows with AutoCount.
9. Sidebar: AutoCount > Companies, click Company B, click the "Entities" tab. In "Add entity" pick "Customer", click "Configure".
10. Click "Edit", leave the path `/debtorbypage`, click "Test", then "Save task".
11. Click the "Mapping" tab.
12. Back on Company A's Customer "Configure mapping" page, resize the browser to 375 px wide, then back to 1280 px.

## Expected
- Step 3: exactly ONE row: `SalesAgent` -> Transform `Text` -> Sorento field `Sales agent code` (added by migration 0029; the other rows are unchanged).
- Step 5: the out record is `{"source_ref": "<company code>:1", "code": "300-Z001", "name": "Sim Debtor", "sales_agent_code": "AGENT X III", "is_active": true}`: trimmed, level suffix `III` kept.
- Step 6: the out record has NO `sales_agent_code` key at all (not `null`, not `""`).
- Step 8: the preview has a `SalesAgent` column; values match AutoCount, blanks are empty.
- Step 10: the save succeeds (toast).
- Step 11: five rows in this order: `AccNo` (Code), `CompanyName` (Name), `Phone1` (Phone number), `SalesAgent` (Sales agent code), `IsActive` (Is active).
- Step 12: at 375 px the mapping table scrolls inside its card with no page-level horizontal scroll and the `SalesAgent` row is visible; at 1280 px it is unchanged.
- Push (only once sorento CUSTOMER-SALES-AGENT is deployed): each pushed customer with an agent carries `"sales_agent_code": "<AutoCount code, trimmed>"`; customers with a blank agent carry no `sales_agent_code` key. Against a Sorento WITHOUT that lane, customers that have an agent are rejected (422 unknown field).
