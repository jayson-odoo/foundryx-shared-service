## Setup
1. Copy on this PR head. Deploy with `python -m scripts.bootstrap_db` (module migration `0001_hub_connector_init` creates `app_hub_connector`; no core migration).
2. Sign in as the tenant Admin, Services -> install "Hub Connector", sign out and in again.
3. A CRM with PR #2801 deployed, a connector integration whose key user has the explicit `integration.connector.read` grant and company `<CO>`, rate limit at least 60/min. Note the CRM address, the company code and the key.
4. If the test copy cannot reach a CRM, any server answering the four feed routes in the #2801 shape works (the PR's tests use one).

## Steps
1. Settings -> Integrations -> Create -> provider "CRM stock feed"; CRM address, Company code, Connector key; Save; Test connection.
2. Hub Connector -> Hubs -> gear -> Sync now.
3. Create; Name "EcoHub", Code "ecohub", Receiver URL `https://webhook.site/<your id>`; Create; note the signing secret; close.
4. Click the EcoHub row; Customers tab -> Create; Customer code "C-001", Customer name "Test customer one", leave Locations and Brands empty; Add.
5. Row "..." on Test customer one -> Preview.
6. Click the row; pick one Location and one Brand; Save; row "..." -> Preview.
7. Create a second customer "C-002" / "Test customer two" with a different Location and the same Brand; Preview it.
8. Details -> Edit -> Show price on -> Save; Preview Test customer one again.
9. Details "..." -> Hub keys -> Create, name "EcoHub"; copy the key; call `GET <api>/api/v1/hub-connector/products?customer=C-001` with `Authorization: Bearer <key>`, then `?customer=NOPE`.
10. Deliveries tab; then Filters -> Status -> Delivered.
11. History tab.
12. Back to Hubs; Filters -> Show price -> Yes.
13. Gear -> Scheduled tasks; row "..." on "Stock sync from the CRM" -> Run now.
14. Workflows -> create a workflow -> open the node palette, search "Hub".
15. Repeat steps 4-5, 10, 11 and 13 at phone width (375px).

## Expected
- Step 1: "Connected. The CRM lists N locations for this company." Step 2: toast "N products synced"; Location and Brand pickers then list the CRM's dealer locations and brands.
- Step 5: an empty Preview (a new customer sees nothing).
- Step 6: only products of the chosen brand; In stock = Yes exactly when the CRM's available quantity summed over the chosen location(s) is above 0; Incoming = Yes when an incoming line is allocated to a chosen location or not yet allocated. No Price column.
- Step 7: same products, In stock / Incoming may differ from customer one (other location).
- Step 8: a Price column shows the CRM list price (MYR x.xx); "-" where the CRM has none.
- Step 9: JSON `{data:[{code,name,brand_name,in_stock,incoming,list_price,currency}],total,limit,offset}` matching step 8's Preview; `NOPE` = 404 `customer_not_found`.
- Step 10: one row per customer change, dd/mm/yyyy, h:mm am/pm; the Status filter narrows to Delivered rows; webhook.site bodies carry `sequence`, `full`, `items`, `removed`, header `X-Hub-Connector-Signature`.
- Step 11: newest first; rows for Hub created, Customer added (x2), Customer locations / brands changed: C-001, Show price changed (No -> Yes), Hub key created; Who = your name, On behalf of "-".
- Step 12: only EcoHub listed.
- Step 13: Last run updates to now, Last error "-"; "Hub delivery retries" listed with Every minute.
- Step 14: "Hub customer availability" and "Sync hub stock now" in the palette.
- Everywhere: no Active/Trashed switch on Hub Connector lists, no ids on screen, no horizontal page scroll at 375px.
