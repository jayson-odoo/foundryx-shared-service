# Hand test - PR #180 SS-MIGRATION-SYNC (keep syncing from respond.io until cutover)

## URL
crew test copy

## Setup
- Schema change: module migration `0024_omni_migration_sync` adds two new empty tables, `app_omnichannel.migration_syncs` and `app_omnichannel.migration_sync_hints` (idempotent SQL posted on the PR as `crew-migration`).
- Sign in as a tenant Admin (holds `omnichannel_migration.manage`).
- A respond.io connection under Settings > Integrations that reads a SMALL respond.io test space (a few contacts with messages). respond.io is only read, never written. Its API address must be the normal `https://api.respond.io/v2`.
- A NEW empty workspace for this test (Omnichannel > Settings > Workspaces > New, name `Sync test <today>`). Do NOT use MyFuji Platform.
- The test copy runs Celery in eager mode (no beat). Where a step says "run the sweep", run this from `service_backend/` on the test copy:
  `.venv/bin/python -c "from app.database import SessionLocal; from modules.omnichannel.services.migration_sync_service import run_due_syncs; db=SessionLocal(); print(run_due_syncs(db)); db.close()"`
- You need a phone that can message one of the respond.io test space's channels (to create a new message on respond.io during the test).

## Steps
1. Sidebar: Omnichannel > Settings > Migration, click "New migration".
2. Pick the test respond.io connection and the workspace `Sync test <today>`; map the channels (or leave them on "Skip for now").
3. Click "Run dry run", wait until "Start migration" is enabled, click "Start migration", wait for "Done".
4. On that migration's detail page, scroll below the report to the "Continuous sync" card.
5. Click "Start syncing" and read the status line.
6. From your phone, send "sync test 1" to the respond.io test channel; wait until it shows in respond.io.
7. Click "Sync now".
8. Sidebar: Omnichannel > Inbox, open that contact's conversation in `Sync test <today>`.
9. Back on the migration detail page, click "Copy" next to the webhook link.
10. In a terminal run `curl -s -X POST -H 'Content-Type: application/json' -d '{"contact":{"id":<respond.io id of that contact>}}' '<pasted link>'`.
11. Run the same curl with the last character of the link changed.
12. From your phone send "sync test 2".
13. Run the sweep command from Setup, then reload the step 8 conversation.
14. Click "Pause".
15. Click "Resume".
16. Click "Rotate link", then Cancel in the dialog.
17. Click "Rotate link", then confirm.
18. Re-run the step 10 curl with the OLD link.
19. Click "Copy" and run the step 10 curl with the NEW link.
20. Click "Stop syncing (cutover)" and confirm in the dialog.
21. Open the step 8 conversation and look at the composer.
22. Resize the browser to 375 px wide on the migration detail page, then back to 1280 px.

## Expected
- Step 4: the card shows only a "Start syncing" button.
- Step 5: status badge "Active"; the respond.io contact count equals the dry run's Contacts "Fetched", with "Full sweep about N min"; the line reads "Syncing every 15 min. Last sync <time>: +0 contacts, +0 messages, 0 errors. Next sync <time>." (before the first sync there is no "Last sync" part).
- Step 7: "Last sync" moves to now and the line shows "+1 messages" (or "+1 contacts, +1 messages" if your phone was a new contact), 0 errors.
- Step 8: "sync test 1" is in the thread exactly once, at its respond.io time; the thread is NOT marked unread; no workflow or AI reply fired in the Shared Service.
- Step 10: curl prints `{"ok":true}`.
- Step 11: curl prints `{"detail":"Not Found"}`.
- Step 13: "sync test 2" appears once.
- Step 14: badge "Paused".
- Step 15: badge "Active".
- Step 16: dialog title "Rotate webhook link?", body "The current link stops working."; after Cancel the link is unchanged.
- Step 18: `{"detail":"Not Found"}`.
- Step 19: `{"ok":true}`.
- Step 20: the card reads "Stopped <time>"; only "Start syncing" is offered.
- Step 21: if the contact wrote within the last 24 hours the composer accepts free text (no 24-hour template lock); otherwise the template lock shows as before.
- Step 22: at 375 px the buttons wrap onto several lines, the webhook link input is full width, no sideways page scroll; at 1280 px the buttons sit on one row.
