# Hand test - PR #180 SS-MIGRATION-SYNC (keep syncing from respond.io until cutover)

## URL
crew test copy

## Setup
- Schema change: module migration `0025_omni_migration_sync` adds two new empty tables, `app_omnichannel.migration_syncs` and `app_omnichannel.migration_sync_hints` (idempotent SQL posted on the PR as `crew-migration`).
- Sign in as a tenant Admin (holds `omnichannel_migration.manage`).
- A respond.io connection under Settings > Integrations that reads a SMALL respond.io test space (a few contacts with messages). respond.io is only read, never written. Its API address must be the normal `https://api.respond.io/v2`.
- A NEW empty workspace for this test (Omnichannel > Settings > Workspaces > New, name `Sync test <today>`). Do NOT use MyFuji Platform.
- The copy runs a Celery worker (not eager mode). Sync jobs are queued and run on that worker a few seconds later. If the copy also runs a Celery beat, the sync sweep runs by itself every 60 s; if it does not, every step that says "run the sweep" means: from `service_backend/` on the copy run
  `.venv/bin/python -c "from app.database import SessionLocal; from modules.omnichannel.services.migration_sync_service import run_due_syncs; db=SessionLocal(); print(run_due_syncs(db)); db.close()"`
  then wait about 15 seconds for the worker and reload the page.
- The Inbox always opens the tenant's DEFAULT workspace (there is no workspace switcher). To read the test workspace's threads use Omnichannel > Contacts, pick `Sync test <today>` in the workspace picker at the top of the list, open the contact, then its "Conversation" tab.
- A phone that is ALREADY a contact in the respond.io test space (it has messages there before step 3), so step 7 tests a new message on an existing contact without any webhook.

## Steps
1. Sidebar: Omnichannel > Settings > Migration, click "New migration".
2. Pick the test respond.io connection and the workspace `Sync test <today>`; map the channels (or leave them on "Skip for now").
3. Click "Run dry run", wait until "Start migration" is enabled, click "Start migration", wait for "Done".
4. On that migration's detail page, scroll below the report to the "Continuous sync" card.
5. Click "Start syncing" and read the status line.
6. From your phone, send "sync test 1" to the respond.io test channel; wait until it shows in respond.io.
7. On the sync card click "Sync now".
8. Run the sweep (see Setup), wait about 15 seconds, reload the migration detail page and read the status line.
9. Open your phone's contact in `Sync test <today>` (Omnichannel > Contacts, workspace picker, contact, "Conversation" tab).
10. Back on the migration detail page, click "Copy" next to the webhook link.
11. In a terminal run `curl -s -X POST -H 'Content-Type: application/json' -d '{"contact":{"id":<respond.io id of your contact>}}' '<pasted link>'`.
12. Run the same curl with the last character of the link changed.
13. From your phone send "sync test 2".
14. Run the step 11 curl again, then run the sweep (see Setup), then reload the step 9 Conversation tab.
15. Click "Pause".
16. Click "Resume".
17. Click "Rotate link", then Cancel in the dialog.
18. Click "Rotate link", then confirm.
19. Re-run the step 11 curl with the OLD link.
20. Click "Copy" and run the step 11 curl with the NEW link.
21. From your phone send "sync test 3" (no curl this time).
22. Click "Stop syncing (cutover)" and confirm in the dialog; wait about 15 seconds (run the sweep if the card still reads "Stopping") and reload.
23. Reload the step 9 Conversation tab and look at the messages and the composer.
24. Resize the browser to 375 px wide on the migration detail page, then back to 1280 px.

## Expected
- Step 4: the card shows only a "Start syncing" button.
- Step 5: status badge "Active"; the respond.io contact count equals the dry run's Contacts "Fetched", with "Full sweep about N min"; the line starts "Syncing every 15 min." (a "Last sync <time>: +N contacts, +M messages, E errors." part appears once a sync has run).
- Step 8: "Last sync" is now and shows "+1 messages", 0 errors (Sync now checks every contact, so the existing contact's new message is found without a webhook).
- Step 9: "sync test 1" is in the thread exactly once, at its respond.io time; no workflow or AI reply was sent from the Shared Service.
- Step 11: curl prints `{"ok":true}`.
- Step 12: curl prints `{"detail":"Not Found"}`.
- Step 14: "sync test 2" appears once.
- Step 15: badge "Paused".
- Step 16: badge "Active".
- Step 17: dialog title "Rotate webhook link?", body "The current link stops working."; after Cancel the link is unchanged.
- Step 19: `{"detail":"Not Found"}`.
- Step 20: `{"ok":true}`.
- Step 22: the card reads "Stopped <time>"; only "Start syncing" is offered.
- Step 23: "sync test 3" is there exactly once (the final sync on Stop checks every contact). Because you wrote within the last 24 hours the composer accepts free text (no 24-hour template lock) once the workspace has a connected channel; with every channel skipped it shows "No active channel is connected to this workspace." as before.
- Step 24: at 375 px the buttons wrap onto several lines, the webhook link input is full width, no sideways page scroll; at 1280 px the buttons sit on one row.
