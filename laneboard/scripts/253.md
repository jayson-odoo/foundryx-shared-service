# Hand test - PR #253 FEEDBACK-SUBSCRIBE (share link, phone code, followers, History)

## URL
crew test copy: operator app (sign in as the lane demo tenant admin) and, for the visitor steps, a private window on the same host.

## Setup
- Crew test copy of branch `claude/feedback-share-subscribe-oqhgpm` (head per crew-done), migrated to ideation `0024_ideation_history` (`python -m scripts.bootstrap_db`).
- **Stand-in product (no hand-inserted connection).** The phone step asks the tenant's product to look the phone up and send the 6-digit code. On the copy nothing may reach a real product, so run these in the copy's backend folder (venv on, the copy's own `.env`):
  1. `python -m scripts.fake_feedback_product --port 8099 --known 60123450002="Contact B"` and leave it running. It answers the lookup for the listed digits and PRINTS each code (`CODE for +60123450002: 123456`) instead of sending WhatsApp.
  2. `python -m scripts.crew_feedback_standin seed --allow-non-dev` (add `--tenant <slug>` if the lane tenant is not `default`). This activates a "ZZT stand-in product" consumer connection pointing at `http://127.0.0.1:8099` and parks the tenant's real consumer connection, so the copy sends no lookup, code or status poke to a real product. It refuses `ENVIRONMENT=production`, any non-development environment without `--allow-non-dev`, and any database host that is not this machine.
  3. When finished: `python -m scripts.crew_feedback_standin restore --allow-non-dev`. This removes the stand-in and reactivates exactly the connections it parked.
- A workspace contact "Contact B" with phone `+60 12-345 0002` (so the follower has an SS contact to receive updates). A non-test feedback item FB-A whose submitter is a different contact, linked to one business requirement on the same product.
- Note the counts before: FB-A followers, FB-A History rows, the requirement's linked feedback.

## Steps
1. Operator: open FB-A, open the "..." menu, then Share link. Click the copy button.
2. In a private window, open the copied link.
3. Click Follow. In "Your WhatsApp number" type `012-345 0002` and click Send code.
4. Read the code from the stand-in terminal. Type it and click Continue.
5. Operator: reload FB-A and open the Followers tab, then the History tab.
6. Operator: Followers tab, click Create. In Contact, type part of the submitter's name, pick the submitter and click Add.
7. Open the Contact dropdown again without closing the dialog.
8. Click Cancel, then click Create again, then open the Contact dropdown.
9. Operator: open the business requirement, Feedback tab. Right-click (on a phone: long-press) FB-A's row and choose Unlink. Wait for the countdown to finish without reloading.
10. Open FB-A, History tab.
11. Repeat steps 2 to 4 with an unlisted number, e.g. `012-345 0099`.
12. Repeat steps 1 to 10 at about 375 px wide.
13. Clean up: unfollow Contact B (Followers tab, right-click the row, Remove), re-link FB-A to the requirement, then run the `restore` command from Setup.

## Expected
- Step 2: FB-A read-only: title, status, timeline, comments by first name, counts. No phone numbers anywhere.
- Step 3: the dialog moves to "Code sent to ..."; the stand-in terminal prints one CODE line.
- Step 4: the button reads "Following" and the follower count goes up by 1.
- Step 5: Contact B is listed, Added by "Themselves". History top row: "Follower added", To = Contact B.
- Step 6: red line "This contact raised the request and already gets its updates."
- Step 7: the search box is empty and the full contact list is offered, not only the earlier match.
- Step 8: no contact chosen, no red line, Add disabled; the full list is offered.
- Step 9: the row leaves the Feedback tab once the countdown ends, with no reload.
- Step 10: top row "Unlinked from business requirement", Who = you, From = the requirement's title.
- Step 11: "This number isn't registered with ..." and nothing else happens; the stand-in prints no CODE line.
- Step 12: same results; dialogs and lists fit the width with no sideways scrolling.
- Step 13: every count matches the "before" line; the tenant's real consumer connection is active again.
